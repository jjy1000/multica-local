**Status:** 0.3.16 source-complete; DMG ship deferred.

**Three Labs flags now wired:**

1. **`claude_science`** — full Multica-native skills browser at
   `/experimental/claude-science`. 291 skills rendered as a 3-column
   panel (categories / list / markdown body). Data sourced from
   `GET /api/experimental/claude-science/skills` (new in
   `server/internal/handler/claude_science_skills.go`); categories
   pulled from bundled manifest.

2. **`pythia_oracle`** — Pythia Python service no longer spawns Ollama.
   `_complete()` POSTs to `/api/runtime/llm-call` which routes every
   LLM call through Multica's provider chain. New handler at
   `server/internal/handler/runtime_llm_call.go`: source_ip 127.0.0.0/8
   strict, 60/min rate limit, JWT auth, provider CLI fallback list
   matching daemon probe order.

3. **`mythos_swarm`** — catalog flag only in 0.3.16. RDT three-stage
   (prelude / recurrent loop / coda) → Multica squad topology
   documented in `.omc/plans/0.3.16-full-integration.md` Phase E.
   Engine / migration 150 / install handler / sidebar entry all deferred
   to 0.3.16-patch.1.

**Prevention contract additions:**

- **Packaged app must inject MULTICA_AGENT_RUNTIME_URL +
  MULTICA_API_TOKEN** at pythia-manager spawn (best-effort: silent
  skip if profile not logged in, falls back to Ollama path).
- **Pythia Python wrapper pre-flights deps and exits 127** with a
  pip hint rather than letting uvicorn crash with a traceback.
- **Loopback-only endpoints** must use the same `parseNetIPAddr +
  ip.IsLoopback()` guard as `clientIPForRateLimit`; XFF must not be
  honoured on these routes.
- **Pythia SKILL must mention the runtime bridge** so the agent
  doesn't fall back to Ollama configuration steps when the bridge is
  already in place.
