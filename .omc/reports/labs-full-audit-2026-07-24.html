01P0 — Ship blockers (2)

P0-1 · multica lab delegate cannot authenticate from inside an agent task

P0
Lane: Backend + Security Contract: 0.3.61 MULTICA_API_TOKEN bridge Files: cmd_lab.go:118 · cmd_auth.go:74-92

Daemon 在 daemon.go:3641 注入 MULTICA_API_TOKEN（alias of mat_ task token）。cmd_experimental 读 MULTICA_API_TOKEN（work）。cmd_lab 走 newAPIClient → resolveToken，只读 MULTICA_TOKEN。在 agent task 上下文里 MULTICA_TOKEN 未设、inAgentExecutionContext() 为 true → resolveToken 返回 "" → newAPIClient 抛 mat_ 错误。CLAUDE.md §"0.3.61" 声称两个 CLI 都读 MULTICA_API_TOKEN，CLI 不兑现自己的合约。

// cmd_lab.go:118
client, err := newAPIClient(cmd)
// cmd_auth.go:74-92 — resolveToken:
if v := strings.TrimSpace(os.Getenv("MULTICA_TOKEN")); v != "" { // ← only checks MULTICA_TOKEN, not MULTICA_API_TOKEN
  return v
}
if inAgentExecutionContext() { return "" }   // ← agent task context short-circuits to empty
if os.Getenv("MULTICA_DAEMON_PORT") != "" { return "" }
profile := resolveProfile(cmd)
cfg, _ := cli.LoadCLIConfigForProfile(profile)
return cfg.Token

Impact: 0.3.63 宣传的 agent-lab delegation 工作流，对唯一会用它的角色（daemon 任务里的 agent）完全不可用。CLI fall through 到 user-global config token，但 MULTICA_DAEMON_PORT 已 set → 失败关闭 → agent 拿到空的无效 token。

Fix: 在 resolveToken 里把 MULTICA_API_TOKEN / MULTICA_API_TOKEN_FILE fallback 放到 MULTICA_TOKEN 之前；inAgentExecutionContext() 短路只对 MULTICA_TOKEN 路径生效（alias 本身就是 task-scoped token，正是该用的）。

P0-2 · GetTaskTokenByHash not bound to (task_id, agent_id) — token replay across workspace for 24h

P0
Lane: Security Contract: S3 (token propagation) + 0.3.61 bridge promise Files: task_token.sql · auth.go:75

mat_ token 是 20 字节随机（160 bit 熵），CLAUDE.md / jwt.go:49-52 文档"bound to (agent, task)"。DB 层只校验 hash + expiry，不校验 task_id / agent_id。24h TTL 内同 workspace 任何 task 都能用同一个 mat_ token 通行：

-- name: GetTaskTokenByHash :one
SELECT * FROM task_token
WHERE token_hash = $1 AND expires_at > now();   -- ← no task_id/agent_id bound

Impact: 单 user fork 里实际对手是 user 自己，但 prompt-injected agent 若曾持 mat_ token，可调 POST /api/issues / DELETE /api/user-plugins / POST /api/experimental/pythia_oracle/forecast/issue 冒充任何 agent（只要能猜 UUID）。Workspace-scoped 爆炸半径，24h 窗口。

Fix: 改为 WHERE token_hash = $1 AND task_id = $2 AND agent_id = $3 AND expires_at > now()，从 server 已信任的 X-Task-ID / X-Agent-ID 头取 (task_id, agent_id) 传入。Token replay 仍可能在 attacker 同时拿到 token + header 时发生，但需要更深的攻陷（任意文件读）。

2.4 Security & data safety lane (8)

SEC-P1-1 · User-plugin inline runtime 继承 os.Environ()；python3 -I 不够

P1
Contract: S1 (sandbox escape) File: user_plugin_runtime.go:145-152, 316

cmd := exec.CommandContext(execCtx, "python3", "-I", entryFileName)，cmd.Env = pluginRuntimeEnv(slug, envDir) = append(os.Environ(), ...)。父 server 继承 user 完整 env（JWT、profile paths、PYTHONPATH、PYTHONSTARTUP）。python3 -I 启用 isolated mode 但不清 PYTHONPATH / PYTHONDONTWRITEBYTECODE / PYTHONSTARTUP。恶意 entry.py 读 HOME → ~/.multica/profiles/<name>/config.json → cfg.token，单次运行外泄 user JWT。

Fix: 切到 python3 -I -E -S 且显式构建最小 env：[]string{"PATH="+minPath, "HOME="+envDir, "LANG=C", "LC_ALL=C", "MULTICA_PLUGIN_SLUG=...", "MULTICA_PLUGIN_ENV=...", "MULTICA_PLUGIN_DB=..."}。永远不 os.Environ()。

SEC-P1-2 · MULTICA_API_TOKEN 漏进 plugin env（daemon 共驻时）

P1
Contract: S1 + S3 File: user_plugin_runtime.go:145-152

desktop 共驻部署，server 是 daemon 的 child，daemon 在 daemon.go:3620-3643 把 MULTICA_API_TOKEN 注入自己 env。plugin subprocess 通过 os.Environ() 继承 → 拿到本应只由 task-scoped agent 持有的 token。Plugin 作者可重用来调 POST /api/user-plugins、DELETE /api/experimental/{flag} 等。

Fix: 同 SEC-P1-1 — 显式最小 env。

SEC-P1-3 · isBlockedEnvKey 不拦截 PYTHON* env vars

P1
Contract: S4 (CustomEnv override) File: daemon.go:4568-4582

函数正确拦截 MULTICA_*、HOME、PATH、USER、SHELL、TERM、CODEX_HOME，不拦截 PYTHONPATH、PYTHONSTARTUP、PYTHONDONTWRITEBYTECODE、PYTHONHASHSEED、PYTHONIOENCODING、PYTHONUNBUFFERED、PYTHONBREAKPOINT。今天 pythia 不从父 env 继承（childEnv 仅由 pythiaRuntimeEnv() 构造），所以是 latent 向量。

Fix: switch 加 PYTHON* 列表（或 wildcard）。

SEC-P1-4 · python3 -I 不禁用 PYTHONSTARTUP；PYTHONPATH 模块影子

P1

Per CPython docs，python3 -I 启用 isolated mode 但不清 PYTHONPATH。PYTHONPATH 目录下的恶意 entry.py 影子真正的 entry。配合 SEC-P1-1，是第二攻击面。
