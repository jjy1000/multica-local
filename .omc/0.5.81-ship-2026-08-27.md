
Root cause chain (none are release defects):

1. **Stale expectation source** — `~/.multica/scripts/verify-desktop-cold-start.sh`
   hardcodes the PRIMARY checkout's apps/desktop/package.json as the
   expected version; before merge-back that tree still says 0.5.80.
   The script honours `EXPECTED_VER=` override — used for all real runs.
2. **Verify-kill cascade killed the bundled DB.** The packaged app ships
   Postgres.app binaries (`~/Library/Application Support/Multica/pg/`,
   reporting "17.10 (Postgres.app)") and boots them against
   `.../Multica/pgdata` on 127.0.0.1:5432 via `startNativePg()`. The
   verifier's "Killing in-flight Multica processes" therefore also kills
   the DB; the following relaunch must boot pg (WAL recovery) + server
   inside the 30 s poll window.
3. **Port collision discovered**: starting OrbStack auto-runs the
   user's `pocketbase` container which maps host :8090 → Multica's fixed
   port. First manual verify attempt lost bind races twice ("address
   already in use", guard-spawn vs app-spawn). `docker stop pocketbase`
   freed the port; container restarted after verification (its host
   forward now loses to Multica — surface to user for a permanent home,
   e.g. remap pocketbase's host port).
