## Governing design law — 任务问题驱动交互模型

**ICP-1 Primary surface = issue.** Runs fire from issues (assignee pick,
comment @-mention, auto-dispatch on create, retry). Labs never require the
user to open the lab view to make something happen. New labs may have an EMPTY
sidebar entry when they are purely issue-driven (precedent planned for
timesfm); standalone-explorer labs (semantica/causal-graph full view) get
sidebar rows for workspace-wide browsing.

**ICP-2 Every lab view binds and shows its issue.** Persist binding via the
existing `?issue=` query param; render the bound issue context bar with a
first-class back-link (breadcrumb) returning to the issue detail page. A lab
view without a live run still shows the bound issue's run RECORDS.

**ICP-3 Lab UIs show history/records, click-through to results, jump to the
task.** Run-record rows are stable-deep-linked
(`/experimental/<suffix>?issue=<id>&run=<runId>`); from a record you can jump
into the producing task/transcript; from the issue timeline (delivered agent
comment / last-result chip) you can jump OUT to the lab record preview.
Bidirectional. No dead ends.

**ICP-4 Iterate-in-issue loop.** User modifies context/params in the issue
(comment, edit fields, reply to agent), re-delivers, then previews the latest
result — either inline on the issue (ExecutionLogSection / last-result chip /
LabOutputPanel) or by jumping to the lab record. Lab records are append-only
history ordered `created_at DESC`.

**ICP-5 Causal awareness is passive, flag-gated, non-blocking.** When
decision tracking (causal_graph flag) is ON, every ran issue surfaces a small
causal icon near the header actions; clicking opens a lightweight subgraph
preview popup. It must never gate or delay runs.

**ICP-6 Infra agents are invisible client-side.** The causal-graph management
team (3 hidden agents + 1 maintenance loop) seeds
`experimental_resource_visibility` rows on install and purges on teardown;
they appear nowhere in pickers/@mention/rosters. Visibility filtering is
fail-open BY DESIGN — never repurpose it as a security boundary.

### 3.0 Causal source taxonomy (the v2 core upgrade)

Edges are ranked by trust class; curator LLM output is only tier D:

- **Tier A — native provenance (zero LLM)**: hook the enqueue/complete seams.
  `EnqueueTaskForIssue`/`EnqueueTaskForMention`/`EnqueueTaskForSquadLeader`
  (`server/internal/service/task.go:528/632/657`) emit a
  `causal_node(type='action')` for the run + `causal_edge('enables')` from the
  triggering node (previous outcome, parent issue, or dependency edge);
  `CompleteTask` (`task.go:1453`) writes `type='outcome'` nodes from the
  final comment + status transition. Mirrors how `decision_sync_listeners.go`
  listens for terminal issues.
- **Tier B — Semantica DecisionRecords (already integrated)**: mirror the
  exported decisions BACK into `causal_node(type='decision')` at
  `decision_sync.go` (provenance block carries
  `{source, issue_id, actor_type, actor_id, occurred_at}` — direct column
  mapping). Bi-directional decision tracking instead of one-way export.
- **Tier C — Pythia hypothesis→evidence closure**: map ledger
  `forecast`(hypothesis w/ probability) + `resolution`(verdict/evidence) pairs
  to `causal_edge('supports'|'contradicts')` between prediction node and the
  resolved outcome node; confidence seeded from scorecard Brier calibration.
  Read via engine proxy endpoints (no new Python needed) or a light
  `GET /scorecard` passthrough; persist only cross-referenced pairs.
- **Tier D — curated triples (LLM, suggested-gated)**: hidden curator extracts
  (subject, predicate, object) from new comments/status transitions; edges land
  `status='suggested'` + `confidence<=0.5` until user confirms (same trust
  ladder as `agent_self_optimization::edits.go`). Evolver proposes
  path-gap edges nightly under the same gate.

## Risks + lessons (v2 additions marked ★)

- **★ Adopt-audit-don't-duplicate**: before writing any planned atom, check
  the target worktree for uncommitted WIP implementing it (this session found

  react-router-dom inside packages/views; desktop pages import it freely,
  shared components must NOT — take query params off `useNavigation()`'s
  searchParams mirror instead (C1 fix precedent).
- **★ Git observations in multi-session worktrees can lie**: clean status
  alongside on-disk files implies index visibility tricks
  (assume-unchanged / skip-worktree) or racing writers; when a diff and
  status disagree, re-run with `-uall` via absolute `-C <worktree>` paths
  and stat mtimes before concluding anything about reality.
- **★ Interface footgun in path helpers**: bash CWD silently resets between
  tool calls here; any relative-path git/ls/inspect command MUST either cd
  first in the same invocation or use absolute paths, or it examines the
  main checkout instead of the worktree under test (cost this session: ~3
  wasted diagnostics + one false contradiction).

- Audit-before-fix per commit (verify-first steps kept inline in specs).

  appear in rosters under DB faults; acceptable (UX-over-authz), but never
  gate privileges through this path; admission of hidden infra loops relies on
  enabled flags + AgentReadiness, NOT the hidden list.

  verbatim literal copies of flag keys across packages (`swarm_topology`
  precedent in orchestrator/swarm_gc): new `causal_graph` literal must be
  replicated identically everywhere and pinned by a catalog test.
- ★ GC/ticker goroutines: no ctx parameter ever; shutdown ordering: HTTP drain
  before scheduler/GC stops.
- ★ claim-response injection touches daemon contract — additions are appended
  text only; never reorder/remove existing briefing blocks (downstream parsing
  is positional in places).
