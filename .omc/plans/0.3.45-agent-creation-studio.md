# 0.3.45 计划: 把"智能体工程师团队"埋进实验室插件

## 用户意图精炼

> "我打算把智能体创建就是智能体创建团队改为实验室插件功能，给它内置掉，用户可以通过问题面板选择智能体创建功能来创建智能体团队、技能或者其他的和智能体宪法可以兼容，你研究一下，这样智能体工程师团队就不在出现在 mulitca 中了"

四层语义拆开:

1. **改名 + 改架构**: 当前并不存在"智能体工程师团队"这个具象产品功能 —— 用户在用现有产品语汇描述一个隐性目标: **让用户"创建 agent / skill / squad" 这类动作从一个被反复宣传的、有专属 tab/menu 的产品功能,降级为一个隐藏在 Labs 里的开发者级 toggle**。运行时不消失,营销面消失。
2. **入口在 issue 面板**: "问题面板选择智能体创建功能" 不是泛指 sidebar,而是要在 **issue detail 页** 有一个动作按钮(或 lab picker 里的二级子菜单),让用户从自己手上的 issue 上下文里拉起 "智能体创建" 工作室。
3. **多个被创建对象**: 一个 lab 入口要能创建 **agent team / skill / 其他兼容智能体宪法的对象**——这意味着 lab 不能只承担"运行一次 chat",而是"运行一个 orchestrator UI,在 UI 里选择要创建 agent/skill/squad",创建动作走普通 POST `/api/agents` 等已有 API。
4. **与 constitution_agent 兼容**: 不能破坏 constitution_agent 已经建立的 contract (skill 走 `loadExperimentSkills` boot loader, agent/autopilot 行只能 install handler 注入, 不能直接 SQL 写, mutex 锁必须在 issue.lab_source 上下文执行)。

## 现状审计 (0.3.44)

### A. "智能体工程师团队"实际指的什么
- **不是独立产品功能**。这个词只作为 (a) `agent_self_optimization` flag 的 autopilot 标题 (`install_agent_self_opt.go:73–74`),以及 (b) `constitution_agent` SKILL.md SOP 用语 7 处出现。
- **没有专门的 UI 入口, 没有 agent_team 表, 没有 batch-create API**。
- 真正可被 "用户感知到的工程师团队" = `agent_self_optimization` flag 详情页 + 受其 visibility 隐藏的「智能体优化专家」agent + 2 条 autopilot (含"智能体工程师团队·每3工作日批量优化") + skillopt-multica Skill。
- `.omc/multica-official-vs-local-diff-2026-07-18.md:160` 已明确: 真正上游的 **Agent Builder Studio** (`handler/agent_builder.go` + `agent-creation-studio.tsx`) **被本地 fork 主动 drop**,因为缺 `agent.system_key` 列 + `runtime_connected_apps` 表,且会与本地 constitution_agent 冲突。

### C. 与 constitution_agent 共存的约束
- `loadExperimentSkills` 已在 `server/internal/service/builtin_skills.go::loadExperimentSkills` boot 时挂载 `apps/desktop/resources/experiments/<flagKey>/skills/.../SKILL.md` —— 任何新 lab 都能复用这套 skill 装载。
- `hidden resource mutex`: 用户在 issue detail 拉起 "agent creation" UI 时,该 issue 不应被新选定的 lab 当作 envelope;反之亦然。若新 lab 不写 `issue.lab_source`,**mutex 不触发**,是正确行为。
- `assignDefaultLabAgentOnUpdate` (`issue.go:2915–2980`) 不需要任何变更,因为新 lab 不经 issue mutex。

### D. catalog.go 8-flag 集合与 Agent Self-Opt 的差异化
- `agent_self_optimization` (issue 1) 是 **policy/visibility-gate**,同时配 `install_agent_self_opt.go` (把"智能体优化专家" + 2 条 autopilot 注入 workspace)。该 install handler 存在但**未在 `router.go:530–552` 注册**(grep 验证) —— 这是 0.3.27 的已知 regression。
- `constitution_agent` 是 **policy/visibility-gate + install handler 已注册**。
- **新"智能体创建" lab 与上述两者都不同**: 它不承担"创建 hidden agent/autopilot",而是承担"运行一个 orchestrator UI 让用户**显式**创建普通 agent/skill/squad"。所以不需要 install handler, 不需要 visibility rows, 不需要 lock 子系统资源。

## 设计方案

### 核心决策 (单选)
**新增一个独立 lab `agent_creation_studio`** (action-type, 非 issue-bound),与其他 8 个 flag 并列,但:
- 不写 `issue.lab_source`
- 不需要 install handler (manifest `installable: false`)
- 不需要 visibility rows (它创建的资源不进 visibility 表)
- 用 `<ExperimentalSection>` 内部新增"按钮"模式 (在 `issue-detail.tsx:1849` footer 把徽章改成可点击的"创建智能体"快捷入口)
- 路由 `/experimental/agent-creation-studio` 是 pre-workspace route,里头渲染一个 orchestrator UI:
  - 三个 tab: **创建 Agent** / **创建 Skill** / **创建 Squad**
  - 每个 tab 复用已有 POST `/api/agents` / `/api/skills` / `/api/squads`(无须后端新增)
  - 显式参数"与智能体宪法兼容": 受 `constitution_agent` flag 启用的 workspace 才能用 `agents.go:CreateAgentRequest.system_key='multica-constitution-compatible'`;不允许时该字段回 400。前端在 toggle off 时把创建按钮灰掉。
- `agent_self_optimization` 与 `constitution_agent` flag **保持现有逻辑, 不动**。它们是 visibility-gate (隐藏应用, 不创建应用), 与 `agent_creation_studio` 是正交关系。

### 落地文件清单 (3 file + 1 manifest)
1. **新 manifest** `apps/desktop/resources/experiments/agent_creation_studio/manifest.json` (仿 `agent_self_optimization/manifest.json`, 改 `installable:false`, `entry_points.action_panel.route: '/experimental/agent-creation-studio'`)。**注意**: 与现有实验最大不同是 `spec.capabilities.agents` / `skills` 都为空(它本身不创建 hidden agent, 它**显式**让用户创建非 hidden 的标准 agent/skill/squad)。
2. **`server/internal/experimental/catalog.go:121–311`** +1 个 Flag literal (Key="agent_creation_studio", DefaultVal=false, RuntimeKind="inline", ManifestPath, Title.zh="智能体创建", Title.en="Agent Creation Studio", 描述 = "在实验室内创建 agent / skill / squad, 创建结果对宪法可见、可在主产品中使用")。
3. **`server/internal/experimental/registry.go`** +1 个 `experimental.ExperimentalFlagKeys()` 返回值 (auto-derived from catalog, 不需要显式枚举, 但需复核 `IsKnownKey`)。
4. **`packages/views/issues/components/issue-detail.tsx:1849` `<ExperimentalSection>`** 改为可点击 —— 当 enabled flag key 是 `agent_creation_studio` 时, footer 显示 "创建智能体 +" 按钮, 跳 `/experimental/agent-creation-studio`。其它 flag 仍按徽章渲染。
5. **`apps/desktop/src/renderer/src/pages/agent-creation-studio-view.tsx` + `routes.tsx:152`** 新文件 + 路由。

### 不动的东西
- `issue.lab_source` / `issue.lab_mode` / `mutex` —— `agent_creation_studio` 不进入这两个列。
- `constitution_agent` / `agent_self_optimization` 详情页 (它们是隐藏 + 自动 dispatch, 不是手动创建)。
- `MulticaSidebar` 顶部不直接露出——**只在 issue 面板 footer + 选中 flag 后跳转**。
