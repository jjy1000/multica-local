# 0.3.45.1 计划: agent_self_optimization 真正接入 (调度器 + 学习流水线 + 实验室历史)

## 用户意图精炼

> "现在主要是对实验室智能体优化插件进行优化，主要是让它定时可以根据 multica 的任务问题（已完结的任务）来进行自我学习和优化相关智能体（不含实验性功能的相关智能体或者技能等）..."

八层语义拆开:

1. **触发方式**: 定时, 周期 = "每四天一次优化" + "工作日 10 点进行", 缺一则推迟到下一次。
2. **采集源**: 用户已完结的 issue (`issue.status='done'`), 排除**任何与实验性功能有关的 agent / skill / autopilot** —— 即 `experimental_resource_visibility` 表里 `flag_key IS NOT NULL` 的 agent, 以及 hardcoded 兜底 mythos_* / claude-* / pythia_*。
3. **任务产出**: 创建 issue 走主面板带 lab 图标 (FlaskConical), 完成后**自动归档**, 主面板按 `archived_at IS NULL` 过滤后只看到**未归档的 self-opt issue**。
4. **可发现性**: 用户在实验室 page (`/experimental/self-opt-history`) 看历史 + 优化报告 + prompt 改进建议; **MVP 只展示, 不写回 agent.prompt** (0.3.46+ 再做 Apply)。
5. **数据源**: 学习数据可以放在外置知识库 —— **MVP 选 mock 文件** `~/.multica/learning-vault/<wsId>/<runId>.md`, 真接 LLM Wiki 留 0.3.46+。
6. **时区**: **系统本地 10:00** (用户决策), 跨重启稳定。
7. **频率语义**: **上次成功 run 后 ≥96 小时 + 工作日 10:00 双门控** (用户决策); 不满足双门控推迟到下个工作日 10:00。
8. **演化性质**: 智能体优化专家 → 自我学习 → agent.prompt / skill 越用越好; 短期 MVP 产出只是**只读建议**。

## 设计方案

### 核心决策
**复用 `service/mythos/supervise.go` 模式新建独立 service `agent_self_optimization.Service`**, 不复用 autopilot scheduler, 但**把 install handler 创建的 2 条 autopilot 标记 archived**, 避免 autopilot scheduler 空转。

落地三层:

1. **数据层 (迁移 158)**
   - 新表 `agent_self_opt_run` (run 元数据 + JSONB 报告 + KB 路径)
   - 新表 `agent_self_opt_run_issue` (增量扫描基础)
   - `issue` 表加 `archived_at TIMESTAMPTZ` 列 (nullable, **加列不加约束**, forward-only)
2. **服务层 (`service/agent_self_optimization/`)**
   - `scheduler.go` 纯函数 `nextTrigger(lastSuccess, now, tz)` 处理工作日 10:00 + 96h 双门控
   - `source.go` 派生"非实验 agent 名单": `experimental_resource_visibility` 行 + hardcoded 兜底 (mythos_* / claude_science* / pythia_oracle)
   - `runner.go` 单 run 流水线: `Collect → Learn (LLM) → CreateIssue (assignee=self_opt_runner) → ArchiveIssue → KBWrite`
   - `service.go` Service struct + Start/Stop/Resume/Tick + `pg_try_advisory_xact_lock` 防多 daemon
3. **表现层**
   - HTTP handler (4 endpoint)
   - 前端 view `self-opt-history-view.tsx` (替换 0.3.27 placeholder 的"详情"部分, 改为 run list + 详情 md 渲染)
   - issue-card 加 `<FlaskConical />` badge 当 `issue.assignee.name='self_opt_runner'`

### 调度语义精解
- `nextTrigger(lastSuccess time.Time, now time.Time) time.Time`:
  1. `minTrigger = lastSuccess.Add(96h)` (如果 lastSuccess nil → `minTrigger = now`)
  2. 从 `minTrigger` 开始找最近的"工作日 10:00 本地"
  3. 工作日: 周一到周五 (Go weekday 1-5)
  4. 找到后返回该时刻; **不立即触发**, 等 ticker 扫到
- `ticker interval = 1 minute` (system service self-check); 不需要每分钟算 nextTrigger 跑, **只在到点触发**

### 数据采集源 (per workspace, single run)
```sql
SELECT i.id, i.title, i.description, i.status, i.updated_at,
       c.body, c.created_at
FROM issue i
LEFT JOIN comment c ON c.issue_id = i.id
WHERE i.workspace_id = $1
  AND i.status = 'done'
  AND i.archived_at IS NULL
  AND i.lab_source IS NULL                       -- 排除实验 issue
  AND i.assignee_id NOT IN (
      SELECT resource_id FROM experimental_resource_visibility
      WHERE flag_key IS NOT NULL AND resource_type='agent'
  )
  AND i.assignee_id NOT IN (
      -- hardcoded safety net: mythos / claude_science / pythia agent
      SELECT id FROM agent WHERE name IN (
          'mythos_prelude','mythos_loop_coder','mythos_loop_researcher',
          'mythos_loop_analyst','mythos_coda','agent-optimizer-expert',
          '智能体优化专家'
      )
  )
  AND i.updated_at >= COALESCE($2, now() - interval '30 days')
ORDER BY i.updated_at DESC
LIMIT 1000
```
