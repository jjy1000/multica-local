# Multica 0.3.16-patch.1 — 4 MCP Servers + Lifecycle Manager (PR 8 + PR 9)

## Context

0.3.15 ships the `claude_science` flag with a full lab-installed workspace
(291 skills + 5 agents + 5 squads), but the agents fall back to LLM
parametric knowledge for domain data because no external data sources are
wired up. 0.3.16-patch.1 ports the model's missing piece: **4 Model
Context Protocol (MCP) servers** that expose structured biology / chemistry
/ patent databases to the runtime, plus a lifecycle manager that spawns /
ensures / stops them on demand and persists per-call counts for the
Labs-side panel.

The 4 servers target the four OpenScience-cloned knowledge bases that
Claude Science agents need to cite instead of hallucinating:

| MCP server | Source | Use case |
| --- | --- | --- |
| `kegg` | KEGG (Kyoto Encyclopedia of Genes and Genomes) REST API | pathway / reaction / enzyme lookup |
| `zinc` | ZINC20 database (CSV bulk + REST) | purchasable compound lookup for medicinal-chemistry |
| `metabolomics_workbench` | NIH Metabolomics Workbench REST | metabolite / NMR / MS dataset retrieval |
| `uspto` | USPTO PatentsView / bulk data | patent prior-art search |

All four are **read-only, public, no auth** (KEGG optionally accepts an
email for higher rate limits, but degrades gracefully without one). That
keeps the CLI / Skill surface clean — `multica mcp kegg pathway get hsa00010`
returns the same JSON the public API returns, no keychain work.

## PR 8 — 4 MCP servers (~600 LOC, ~150 LOC each)

Each server is a standalone Bun TypeScript package under
`apps/desktop/vendor/mcp-servers/<name>/`:

```
apps/desktop/vendor/mcp-servers/
├── kegg/
│   ├── package.json
│   ├── tsconfig.json
│   ├── src/
│   │   ├── index.ts        # stdio JSON-RPC entrypoint
│   │   ├── kegg_api.ts     # HTTP client + path munging
│   │   └── tools.ts        # MCP `tools/list` + `tools/call` dispatch
│   └── tests/
│       └── tools.test.ts
├── zinc/                   # same shape
├── metabolomics_workbench/ # same shape
└── uspto/                  # same shape
```

### Wire contract (stdio JSON-RPC per MCP spec)

Every server exposes:

```
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": "2025-06-18",
    "capabilities": {},
    "clientInfo": {"name": "multica", "version": "0.3.16"}
  }
}
```

→ reply with `serverInfo { name, version }` + `capabilities { tools: {} }`.

The Multica client then calls `tools/list` to discover the server's tools:

```
{kegg}/tools/list →
{
  "tools": [
    {"name": "pathway_get",       "description": "...", "inputSchema": {...}},
    {"name": "pathway_list_genes", ...},
    {"name": "compound_get",      ...},
    ...
  ]
}
```

…then `tools/call`:

```
{"method": "tools/call", "params": {
  "name": "pathway_get",
  "arguments": {"pathway_id": "hsa00010"}
}}
→ {"content": [{"type": "text", "text": "<JSON>"}], "isError": false}
```

### Per-server tool surface (initial scope)

**kegg** (~6 tools):
- `pathway_get(id) → { id, name, classes, genes[] }`
- `pathway_list_genes(id) → string[]` (kegg gene ids like `hsa:1234`)
- `compound_get(id) → { id, names[], formula, mass, reactions[] }`
- `enzyme_get(id) → { id, names[], reactions[], pathways[] }`
- `reaction_get(id) → { id, equation, enzymes[] }`
- `list_databases() → string[]`

HTTP base: `https://rest.kegg.jp`. Endpoint mapping uses KEGG's
single-letter suffix convention (`/get/hsa:1234`, `/list/pathway/hsa`).

**zinc** (~4 tools):
- `substance_get(zinc_id) → { smiles, iupac_name, ... }`
- `substance_search(smiles_or_text, max_results) → [{zinc_id, similarity}]`
- `property_get(zinc_id, props[]) → { props... }`
- `list_subsets() → string[]`

ZINC20 bulk is downloadable only (CSV); API uses
`https://zinc.docking.org/substances/<id>.json`. (ZINC has no public
real-time search API, so we ship `substance_get` only + cache frequently
referenced ids.)

**metabolomics_workbench** (~5 tools):
- `metabolite_get(refmet_id) → { name, formula, inchi_key, sysbio_id }`
- `dataset_search(query, type) → [{dataset_id, title, study_factor}]`
- `study_summary(study_id) → { title, design, sample_count, ... }`
- `metabolite_count(study_id) → int`
- `rest_list_endpoints() → string[]`

Base: `https://www.metabolomicsworkbench.org/rest`. The REST is verbose
(`/data/study/...` paths); one wrapper per endpoint.

**uspto** (~4 tools):
- `patent_get(patent_id) → { patent_id, title, abstract, claims[] }`
- `inventor_search(name, max_results) → [{patent_id, ...}]`
- `assignee_search(name) → [{patent_id, ...}]`
- `classification_lookup(class_code) → [{subclass_title, count}]`

Base: `https://api.patentsview.org/patents/query`. Patent bulk data is
licensed CC0 from `bulkdata.uspto.gov`; PatentsView API requires no key.

### CLI surface (server-side)

Each server gets a thin wrapper under `server/cmd/multica/mcp_<name>.go`,
following the existing `cmd_skill.go` pattern:

```go
// server/cmd/multica/mcp_kegg.go (sketch)
func newMcpKeggCmd() *cobra.Command {
    cmd := &cobra.Command{
        Use:   "kegg",
        Short: "Call the KEGG MCP server",
    }
    cmd.AddCommand(
        // 'multica mcp kegg pathway get hsa00010'
        // 'multica mcp kegg compound get C00031'
        // ...
    )
    return cmd
}
```

A single dispatcher `multica mcp list` enumerates all
bundled + active MCP servers; `multica mcp status <name>` reads the
lifecycle manager's HTTP heartbeat (see PR 9).

## PR 9 — Lifecycle manager + call-count persistence (~200 LOC)

`apps/desktop/src/main/experimental/mcp-manager.ts` extends the
`BaseExperimentalManager` template introduced in 0.3.8.

### Surface

```ts
class McpManager extends BaseExperimentalManager {
  // Per-server child process: Bun runs `bun ./mcp-servers/kegg/index.ts`
  // child.stdin ⇄ child.stdout: JSON-RPC traffic
  // child.on('exit'): marks as 'offline' in heartbeat + persists
  readonly children: Map<McpName, McpChildHandle>;

  // ensureUp(name): spawns the child if not running, waits until
  // `tools/list` returns ≥1 tool (max 30s). Race-tolerant via
  // per-server in-flight Promise.
  ensureUp(name: McpName): Promise<McpStatus>;

  // stop(name): graceful SIGTERM (5s), then SIGKILL.
  stop(name: McpName): Promise<void>;

  // call(name, tool, args): JSON-RPC `tools/call`, returns
  // parsed content. Increments per-call counter atomically.
  call(name: McpName, tool: string, args: Record<string, unknown>):
    Promise<unknown>;

  // list(): heartbeat snapshot for the renderer
  list(): Promise<McpStatus[]>;

  // persist + load counts: experimental_resource_lock + new column
  // experimental_mcp_call_count (workspace_id, mcp_name, calls_last_24h)
}
```

### Storage (forward-only schema, migration 149)

```sql
-- 149_experimental_mcp_call_count.up.sql
CREATE TABLE experimental_mcp_call_count (
  workspace_id   UUID NOT NULL,
  mcp_name       TEXT NOT NULL,
  calls_total    BIGINT NOT NULL DEFAULT 0,
  last_call_at   TIMESTAMPTZ,
  PRIMARY KEY (workspace_id, mcp_name)
);
CREATE INDEX experimental_mcp_call_count_recent_idx
  ON experimental_mcp_call_count (workspace_id, last_call_at DESC);
```

`experimental_mcp_call_count` is **server-side**, not in the lab lock
table, because call counts are workload data (not visibility data). The
lifecycle manager flushes batches of N=100 calls OR every 30s via
`UPSERT … RETURNING calls_total`. Counts reset on `mcp.reset` (not
auto-pruned — the renderer's side panel shows `calls_last_24h` / `total`
from a 24h in-memory cache + DB total).

### Restart / quit teardown

`apps/desktop/src/main/index.ts::before-quit` chain (already
extended in 0.3.8 for `pythia-manager`) gains one more line:
`await stopAllMcpServers()`. No spawn-time registration inside
`mcp-manager.ts` — matches the existing daemon-manager prevention
contract (memory `0.2.97-daemon-autostart-regression.md`).

### Wire shape for renderer

`GET /api/experimental-flags` already returns `installation.counts[]`
per flag (shipped in 0.3.15-patch.1). Add a new wire key per-lab for MCP
fans:

```json
{
  "key": "claude_science",
  "installation": {
    "source": "claude_science",
    "installed": true,
    "hidden": false,
    "counts": [...],
    "mcp_servers": [
      {"name": "kegg", "status": "ready", "tools": 6,
       "calls_last_24h": 142, "total_calls": 3819},
      {"name": "zinc", "status": "offline", "tools": 0,
       "calls_last_24h": 0, "total_calls": 0},
      ...
    ]
  }
}
```

The `LabsFlagSidePanel` is extended with one row per MCP server,
showing status badge (emerald = ready, amber = starting, red = error,
gray = offline-not-bundled) + tool count + last-24h calls.

### Bundle-cli / asarUnpack

`apps/desktop/scripts/bundle-cli.mjs::hasMcpServers()` walks
`apps/desktop/vendor/mcp-servers/<name>/` and copies to
`apps/desktop/resources/mcp-servers/<name>/` if present. Bundle skips
servers whose package.json can't be parsed.

`electron-builder.yml::asarUnpack` gains:
```yaml
- resources/mcp-servers/**
```
(to match the existing claude-science unpack pattern).

## Risk register

| # | Risk | Mitigation |
|---|------|-----------|
| 1 | KEGG rate limit (no key) is 30 req/s/IP | Per-server request queue with token-bucket (10 req/s) + 429 backoff |
| 2 | USPTO PatentsView API has gone down historically | Manager marks server `status=error` on 5xx, retry-on-call (max 1 retry) |
| 3 | ZINC has no public real-time search API | Ship `substance_get` only; document limitation in SKILL.md |
| 4 | Metabolomics Workbench response sizes (large studies) cap to 5MB / call | Truncate at 5MB, return `truncated: true` flag |
| 5 | Bun stdio JSON-RPC vs tsx/node child_process framing | Stick with Bun runtime (bundled in `apps/desktop/.bun` since 0.3.11); reuse `mcp.kegg` style everywhere |

## Roll-forward

PR 8 + PR 9 are 1 logical ship (`0.3.16-patch.1`), gated behind each
other. PR 8 is the larger code body; PR 9 is the lifecycle + storage.
Land PR 8 first (server-only, can land without DMG), then PR 9 with
DMG rebuild.
