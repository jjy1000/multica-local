## Tier 0 — Verifier escalations (NEW, highest priority)

### [M12 → P1] bundle-cli migrate build will fail — **BUILD BLOCKER** [P1]

File: `apps/desktop/scripts/bundle-cli.mjs:149`

`bundle-cli.mjs:149` passes `-ldflags "-X main.version=..."` for the migrate binary, but `server/cmd/migrate/main.go` has NO package-level `var version` declaration. Go build will fail with `'-X flag requires argument of the form importpath.name=value'`.

Currently masked because `go` is rarely in dev PATH → fallback `hasGo()` returns false → migrate build is skipped. The moment someone runs `bundle-cli` with go installed (the canonical packaging path), the whole bundle halts at `execFileSync` (bundle-cli.mjs:152-166).

Fix: split ldflags per binary. The migrate build should skip `-X main.version`. One-line ternary:
```js
ldflags: BUILDS[i].ldflags === false ? '' : fullLdflags
```

Verify by: `go build -ldflags "-X main.version=0.3.1" ./cmd/migrate` from `server/` → must NOT error.

### [F7 → P1] Two `before-quit` handlers race on quit [P1]

Files: `apps/desktop/src/main/index.ts:600` AND `apps/desktop/src/main/daemon-manager.ts:1321`

Both register `app.on('before-quit')` with `event.preventDefault()`. Independent re-entry guards (`isQuittingServer` vs `isQuitting`). On quit:
1. index.ts's `before-quit` fires → `preventDefault` → awaits `stopServerManager` → eventually calls `app.quit()`.
2. daemon-manager's `before-quit` fires nearly simultaneously → `preventDefault` → awaits stopDaemon → calls `app.quit()`.
3. Second `app.quit()` re-fires `before-quit`. First's `preventDefault` was undone. Server may not finish stopping → SIGKILL leak on quit.

Hot path on every quit. Fix: consolidate into a single ordered handler in `index.ts` (stopDaemon → stopServerManager → app.quit()). Remove the daemon-manager-side `before-quit`. 5-line refactor.

### [F6 / "multica daemon start" double-spawn] Memory cross-confirmation [P2]

`daemon-manager.ts:1042` (`maybeRecoverDaemon`) and `:1113` (`tryAutoStartFromMain`) both bypass `withGuard`. TOCTOU race noted in memory `multica-0.3.0-stability-2026-07-03.md` ("`multica daemon start` 双 spawn"). Already in 0.3.0 backlog but audit re-confirmed it's still in source. Add a module-level `starting` guard (mirror `inflightEnsure` from server-manager).

## Process for picking a finding to fix

1. Open `file:line`. Read 30 lines of context in each direction.
2. Confirm claim against the actual code (verifier-verified, but still verify).
3. If confirmed, write a 5-min failing test if behavioral; else just fix.
4. After fix, run `pnpm typecheck` AND a relevant test file.
5. Cite the relevant memory file in the commit body.
6. If a finding turns out wrong or already fixed, remove and add a one-liner to the parent audit's "non-findings" list.
