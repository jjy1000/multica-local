## Incident 1 — electron-builder ENOENT on a stale-worktree symlink

**Symptom**: `pnpm exec electron-builder --mac --dir` run from the **repo
root** failed during packaging with
`ENOENT: stat '/Users/jiangjianyan/jjy/multica-main/apps/desktop/resources/claude-science/agents'`
and left a stray 270 MB `dist/` at the repo root.

**Root cause**: from the repo root, electron-builder resolved
`projectDir` to the repo root, so the default `**/*` file walk swept
`.claude/worktrees/{upstream-040,integration-040}/` — two stale exploration
worktrees whose committed test fixtures
(`server/internal/handler/testdata/claude-science-fixture/claude-science/{agents,skills}`)
are absolute symlinks still pointing at the pre-rename path
`/Users/jiangjianyan/jjy/multica-main/...` (dir renamed 2026-08-01, commit
`6d1417d`). app-builder stats every symlink target; the targets no longer
exist → ENOENT. `.claude/` is gitignored (line 55) but the root-level
walk still reached it.

**Fix**: re-run from `apps/desktop/` (canonical cwd — scopes the walk to
the app dir; `projectDir` logged as apps/desktop). Removed the stray root
`dist/`. Nothing inside the shipped artifact changed.

**Prevention**: see CLAUDE.md Known Stability Surfaces — packaging commands
must run from `apps/desktop/`, never the repo root. The two stale worktrees
remain (left for a deliberate cleanup decision); they are inert as long as
packaging stays in the canonical cwd.

## User-visible behavior delta

- WS frames for `issue:updated` no longer carry `prev_description` /
  `prev_title` (bandwidth: O(workspace connections × description size) per
  autosave → O(1)). Client types never declared these keys; no renderer change.
- Busy-issue timelines now keep the NEWEST comments/activities instead of
  silently freezing at a past point once the cap bites.
- Daemon wakeup handshake works behind `HTTP(S)_PROXY` env (no change when
  no proxy is configured — byte-for-byte direct dial).
- A single rogue WS connection can no longer OOM the server (64 KiB inbound
  frame cap, applied pre-auth; tracked by `inbound_too_large_total`).
