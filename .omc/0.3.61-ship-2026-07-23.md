# Multica 0.3.61 ship — 2026-07-23T01:35Z

`/Applications/Multica.app` 升级到 0.3.61（squad subscriber/inbox schema fix）。
替代 0.3.60。

## 起点

延续 0.3.60 ship 后 daemon.log 暴露的三条 SQLSTATE 23514：

- `issue_subscriber_user_type_check` 拒绝 `user_type='squad'`
- `inbox_item_recipient_type_check` 拒绝 `recipient_type='squad'`
- `agent_task_queue_accountable_matches_originator` 当 `originator_user_id` 被
  member 评论触发 `MergeCommentIntoPendingTask` 写入但 `accountable_user_id`
  永远是 NULL（Go 路径从未写过该列）时失败

诊断过程（与 `/Users/jiangjianyan/Downloads/multica-main` 逐字 diff = 0 验证）
确认：上游 0.4.0 官方版本同款 latent bug，非 fork 回归。本版仅修 schema。

## 修复

`server/migrations/167_squad_subscriber_inbox_constraints.{up,down}.sql`：

```sql
ALTER TABLE issue_subscriber DROP CONSTRAINT issue_subscriber_user_type_check;
ALTER TABLE issue_subscriber ADD CONSTRAINT issue_subscriber_user_type_check
    CHECK (user_type IN ('member', 'agent', 'squad'));

ALTER TABLE inbox_item DROP CONSTRAINT inbox_item_recipient_type_check;
ALTER TABLE inbox_item ADD CONSTRAINT inbox_item_recipient_type_check
    CHECK (recipient_type IN ('member', 'agent', 'squad'));

ALTER TABLE agent_task_queue DROP CONSTRAINT agent_task_queue_accountable_matches_originator;
ALTER TABLE agent_task_queue ADD CONSTRAINT agent_task_queue_accountable_matches_originator
    CHECK (
        (originator_user_id IS NULL)
        OR (accountable_user_id IS NULL)
        OR (accountable_user_id = originator_user_id)
    );
```

`MergeCommentIntoPendingTask` (agent.sql.go:3273) 仍写 `originator_user_id`，
handler 不动。Migration 在生产 PG 应用后 schema_migrations 含 167 行。
