## Ship path (7-step chain + manual repack fallback)

```
# 1. Snapshot — 882M .app backup, 13 tables, 80 config, 6838 KB, git tag
bash ~/.multica/scripts/pre-update-snapshot.sh
# → 完成后自动清理旧 .bak,只保留 /Applications/Multica.app.0.3.69.pre-update-20260731-224823.bak

# 2. migrate up — no pending (207-211 + 213 + 218-227 all already applied)
cd server && go run ./cmd/migrate up
# → all migrations 'skip (already applied)', Done.

# 3. bundle-cli — rebuilt Go binaries at version=0.5.0-dirty
pnpm --filter @multica/desktop bundle-cli
# → 3 binaries + 432 migrations + Pythia + OpenScience + claude-science bundled

# 4. electron-vite build — 1.71s, renderer 12M index, 30 rawRequest occurrences
pnpm --filter @multica/desktop build

# 5. electron-builder --mac --dir  ←— FAILED on `app-builder-bin@5.0.0-alpha.13`
#    ERR: "Get https://github.com/electron/electron/releases/download/v39.8.7/..."
#    proxyconnect tcp: dial tcp :0 — known root CLAUDE.md deadlock
pnpm exec electron-builder --mac --dir

# 5.1 Manual asar repack fallback (per root CLAUDE.md "Ship chain fallback"):
npm install -g @electron/asar          # asar 4.2.1
asar extract /Applications/Multica.app/Contents/Resources/app.asar /tmp/multica-extract
rm -rf /tmp/multica-extract/out/{main,preload,renderer}
cp -R apps/desktop/out/{main,preload,renderer} /tmp/multica-extract/out/
cp apps/desktop/resources/bin/{multica,server,migrate} /tmp/multica-extract/resources/bin/
asar pack /tmp/multica-extract /tmp/multica-new.asar    # 537M
cp /tmp/multica-new.asar /Applications/Multica.app/Contents/Resources/app.asar
cp apps/desktop/resources/bin/{multica,server,migrate} \
   /Applications/Multica.app/Contents/Resources/app.asar.unpacked/resources/bin/

# 5a. desktop-sign-nested-binaries.sh (mandatory; closes 0.3.62 SIGKILL ship-blocker)
bash scripts/desktop-sign-nested-binaries.sh /Applications/Multica.app
# → ✓ signed /Applications/Multica.app + 3 nested binaries; nested 'multica' runs (exit 0).

# 6. Cold-start verify (3-check)
defaults write /Applications/Multica.app/Contents/Info.plist CFBundleShortVersionString 0.5.0
defaults write /Applications/Multica.app/Contents/Info.plist CFBundleVersion 0.5.0
EXPECTED_VER=0.5.0 bash ~/.multica/scripts/verify-desktop-cold-start.sh
# → Cold start succeeded in ~4s; Server is 0.5.0; ports 5432 + 8090 listening; /health ok.
```

The Info.plist bump via `defaults write` was needed because the manual
asar repack path doesn't update Info.plist (the canonical
`electron-builder --dir` path does). Two writes: `CFBundleShortVersionString`
+ `CFBundleVersion` to `0.5.0`. The verify script reads
`/Users/jiangjianyan/jjy/multica-main/apps/desktop/package.json` (the
main fork root) which is still at 0.3.69 — hence the `EXPECTED_VER=0.5.0`
env override. This script wart is documented but not fixed in this
ship; it will sort itself out when 0.5.0 ships to main and the main
root is bumped to match.

## Risk vs outcome

- **Schema-only additive** migration. No row loss, no schema rewrite.
  `IF NOT EXISTS` guards on every ADD COLUMN / CREATE INDEX.
  NULL semantics on `cost_usd_ticks` + `uncosted_*` preserve today's
  behaviour for any code that doesn't read the new columns yet.
- **No application UI changed**. The `client_usage` POST endpoint
  is wired and verified (end-to-end test wrote a row), but no client
  (web/desktop) is calling it yet — the renderer caller is a
  follow-up PR. Dashboard handler does not yet read the new
  cost/uncosted columns — also a follow-up PR.
- **Manual asar repack** validated end-to-end: extracted 0.3.69
  installed asar, replaced renderer + Go binaries, repacked to
  537 MB, deployed to `/Applications/Multica.app`, re-signed with
  self-validating `multica --help` exit 0. The `electron-builder
  --dir` network deadlock is known and documented in root `CLAUDE.md`
  "Known Stability Surfaces" — the 0.3.63 ship logged the
  `app-builder-bin@5.0.0-alpha.12` IPC pipeline as the root cause; the
  alpha.13 pin bumps the same number. Tracked for resolution before
  0.5.0-batch (fork cycle ~1 month).
- **Row parity**: workspace=1 / issue=244 / comment=1510 / agent=96 /
  user_plugin=0 / client_usage_daily=0 (1 row inserted by the
  end-to-end test) / task_usage=1735 / task_usage_hourly=681. Drift
  expected on the new `client_usage_daily` table (1 row from the
  end-to-end test); everything else unchanged from the 0.3.69
  golden baseline.
