## 内容

### 修复:0.5.5.1 漏改的 Labs tab UI 入口

0.5.5 + 0.5.5.1 后端/服务逻辑已经让 `agent_creation_studio` + `agent_self_optimization` 完全脱离实验域(catalog `DefaultVal: true`,self-opt flag gate stub 化,9 个 HTTP handler 解 gating),**但 Settings → Labs tab 仍然显示这两个 flag**(截图证据:`packages/views/settings/components/labs-tab.tsx::flags.map` 无任何过滤)。

用户能在 Labs tab 看到"智能体自优化"toggle,即便 toggle 处于 enabled 状态,也会误导用户"这是个实验,我不想要可以关掉"。更糟的是:用户真去关掉 self-opt 旗标,**不会阻止 self-opt 跑**(flag 已经是 stub always-true),但**会让 user 失去 toggle 信心 + 心理上认为"product 行为奇怪"**。

### 改动

- `packages/views/settings/components/labs-tab.tsx`:
  - 加 `import { useMemo }` (line 3)
  - 加 `PRODUCT_LEVEL_LAB_KEYS` Set,包含 `agent_creation_studio` + `agent_self_optimization`
  - 加 `displayedFlags` useMemo,在 `flags.map` 之前过滤掉产品级 flag
  - `flags.map` → `displayedFlags.map`
- `apps/desktop/package.json`: 0.5.5.1 → 0.5.5.2

### 跟 0.5.5 阶段的 HIDDEN_LAB_KEYS 对齐

0.5.5 已经在 `packages/views/issues/components/pickers/lab-picker.tsx` 硬编码了同样两个 key(issue LabPicker 不显示)。0.5.5.2 把同样的"产品级黑名单"延伸到 Settings Labs tab —— **两个 UI 层防御 catalog drift**。

未来 0.5.6 完全删除 catalog Flag 时,这个 `PRODUCT_LEVEL_LAB_KEYS` 集合也一并消失。
