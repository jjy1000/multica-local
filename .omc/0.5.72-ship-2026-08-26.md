## Lessons

- **Manual port > broken cherry-pick** when the cherry-pick pulls in
  modules the fork doesn't have. The `index.ts` rewrite was 50 LOC
  (just the webPreferences block) — much smaller than trying to also
  port `AuthSessionCoordinator` + `NotificationGate` +
  `MainRendererMessageQueue` + `dev-log` (would have been ~300+ LOC
  and a fork-direction choice the user should make explicitly).
- **`createRendererWebPreferences` overrides parameter** preserves the
  principle that the helper pins the security-relevant defaults while
  letting fork-specific extensions (like `webviewTag: true`) override
  cleanly. Avoids a fork-only branch inside the helper.
- **Test seams are durable**: the `effectiveQ issuestatus.Querier` seam
  added in Task B is the kind of test-only field that's invisible to
  production callers (nil-checked, falls back to `s.queries`) but
  unblocks unit tests that walk custom-status code paths. Worth the
  3 lines of indirection.
- **PDF plugin comment is an "explainer" comment**, not a contract
  comment. Rewriting it to reflect the fork's actual download flow
  (no CloudFront) makes the comment useful again — the next reader
  won't be confused about why CloudFront is referenced in a fork that
  has no CloudFront.
