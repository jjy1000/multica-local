## Incident 1 — pre-update snapshot abort: disk full (99%)

**Symptom**: snapshot aborted at Step 4/6 "Rsync KB vaults" with the error
swallowed by `2>/dev/null` + `set -euo pipefail`.

**Root cause**: `/System/Volumes/Data` was 99% full (11 GiB free). The KB
backup dir `~/Documents/.backup` had accumulated **89 GiB across 164
`llm-wiki-pre-update-*` snapshots** — the script prunes `.app` `.bak`s but
never the KB snapshots. rsync of the 1.2 GiB vault hit ENOSPC mid-copy and
silently exited.

**Fix**: user-approved deletion of 135 old KB snapshots (kept
20260805-161915 + today's). Disk went 11 GiB → 119 GiB free. This is a
pre-existing script gap, not a Multica bug.

## Incident 2 — pre-update snapshot abort: iCloud mmap timeout (still at Step 4)

**Symptom**: after freeing disk, the rsync still aborted instantly.

**Root cause**: `rsync ... mmap: Operation timed out` on
`.llm-wiki/history/*.json` — iCloud is actively downloading the user's
Documents folder (`brctl status` showed an active downloader with
`downloading: 0.0%` + `BRInternalDomainError`). Files evicted to iCloud can't
be mmap'd in time. The `Documents/llm wiki` vault carries `com.apple.provenance`
xattr (iCloud-managed).

**Fix (user-approved)**: patched `pre-update-snapshot.sh` Step 4 — the KB
rsync now runs under `timeout 120` and a failure WARNs + skips instead of
blocking the ship. Rationale: Multica's ship chain never touches `/Documents`;
the `.app` + PG + config backups are the load-bearing data-safety points, and
the KB backup target lives inside the very iCloud-synced folder causing the
problem. Original script backed up at `pre-update-snapshot.sh.bak-20260806`.

## User-visible behavior delta

- A saturated agent session is now classified `agent_error.context_overflow`,
  **retired from the resume pointer**, and the next task cold-starts — no more
  infinite replay of "context window full".
- A context-exhausted run reports a clear failure (quotes the structured
  reason) instead of an empty/misleading success, and its provider notice is
  never posted as the agent's answer.
- Scheduled autopilot dispatch now bumps the empty-claim cache — idle runtimes
  no longer return empty claims until the TTL expires.
- The unsubscribe/subscribe control no longer flashes the wrong state before
  the query resolves, no longer double-fires on a fast double-click, and says
  so when a toggle fails.
