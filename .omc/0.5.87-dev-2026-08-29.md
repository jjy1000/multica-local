## Workstream 1 — mythos async-engine unification (swarm orchestrator port)

Commit `19d4c506f`. The mythos engine absorbs the swarm orchestrator's three remaining hardening patterns, completing the single-engine consolidation started by the 0.5.86 swarm freeze:

1. **Stalled-run reap** — new `ListStalledMythosRunsForGC` (`pkg/db/queries/mythos_run.sql`, sqlc-generated) + `service/mythos/reaper.go` (new). Two stall clocks, one per status:
   - `running` rows with `started_at` older than **24h** — sole pipeline / pre-coda enhancer rows have no supervision heartbeat, so wall-clock age is the only honest clock (the in-process RDT pipeline is bounded far under 24h; 24h also matches `SupervisionMaxLifetime`). This is the dev-record's "3 stuck `running` since 08-24" class: `ResumeSupervision` only re-adopts `status='supervising'`, so a restart-mid-pipeline row could never terminate.
   - `supervising` rows whose `supervision_state.last_check_at` heartbeat is staler than **1h** (COALESCE to `started_at`) — the live goroutine refreshes it every 30s tick, so >1h means the goroutine died without a resume. A healthy goroutine is unreachable by a 6h sweep.
   - Reaper loop: 6h interval, **boot-sweep-first** (0.5.60 starvation lesson), 60s per-sweep timeout, batch cap 100, per-row best-effort. `StartStalledRunReaper` takes no context (0.5.39 SwarmGC lesson); `Stop` folded into `Service.Stop`. Supervising rows keep their timeline: `abort_reason=stalled_reap` is **merged** into the existing supervision_state (tick history preserved); `running` rows are failed by status flip alone (no state blob invented).
2. **Per-tick timeout** — supervise loop wraps `tickSupervision` in `context.WithTimeout(ctx, 2*SupervisionTickerInterval)` (port of `service/swarm/orchestrator.go:318`); `DeadlineExceeded` lands in the existing degrade branch and the next tick retries.
3. **Heartbeat from t=0** — the supervise loop's initial persist stamps `last_check_at` (previously zero-time, which read as "stale" to the reap clock).

Wiring: `cmd/server/router.go` starts the reaper beside the `ResumeSupervision` walk (guarded by `pool != nil`); shutdown needs no new code (`MythosService.Stop()`).

Tests: DB-less `service/mythos/reaper_test.go` (new `reapQ` seam, mirrors the `tickQ` pattern; merge-preserves-history, running-row-no-state-write, corrupt-blob-replacement, per-row-failure continuity, list-error/empty no-op, nil-safe double Stop) + DB-backed `handler/mythos_stalled_run_gc_test.go` pinning the SQL selector semantics (condemned: 48h running + 3h-stale heartbeat supervising; spared: fresh running, fresh heartbeat, `{}`-state COALESCE, terminal completed). **Test-margin lesson**: SQL `now()` runs after the Go clock, so "exactly 1h" rows flip sides — spared margins sit at 55min.
