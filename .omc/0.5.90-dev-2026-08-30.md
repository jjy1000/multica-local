## 本周期踩坑与教训

1. **死路发现**：0.3.31 的 enhancer 链路 schema/runner/UI tab 全有，但 HTTP 契约没字段——"全链存在"不等于"可达"，调研阶段要用触发面倒推。
2. **断言路径嵌套**：claim 响应是 `task.agent.instructions` 不是顶层 `agent`——首轮 live 断言读错路径假阴性两次（0.5.89 教训"脚本三连坑"的镜像）。
3. **psql 命令标签污染变量**：`psql -Atc "INSERT...RETURNING"` 的 stdout 带 `INSERT 0 1` 尾巴 → `$(...)` 捕获两行 → 后续 JSON body 非法。`-Atq` + `head -1`。
4. **runtime owner**：owner NULL 的 runtime 被视为私有，API 建 agent 会拒——live 种子运行时要把 owner_id 指到测试用户（打包路径的合成 stub 走 DB 直插不受此限）。
5. **幂等去重的可测性**：`HasPendingTaskForIssueAndAgent` 会把 wake 吞掉（正确）——要验证 wake 就必须先清掉绑定任务，"正确行为"和"要测的行为"需要脚本制造区分。
6. **校验顺序**：roster 查找放契约校验前会让无效请求 400 在误导性的错误上——便宜的 enum/root 校验永远先行。
7. 布尔断言口径：psql 布尔 `||` 文本拼出 `true/false` 不是 `t/f`（两种写法都出现在库内，比对字符串时以实际输出为准）。
