## ⚠️ 事故记录: bump commit 卷入 fix commit（管道吃退出码第 5 次）

`46aa5cfc0` 的 `git add` 路径把已 bump 的 `apps/desktop/package.json` / `CLAUDE.md` /
`AGENTS.md` 一并 staged → 后续独立 `git commit -m "chore(release): bump to 0.5.129"`
变成 nothing-to-commit（exit 1）, 但命令写成 `git commit … 2>&1 | tail -1 && ship…`——
**管道末端 tail 吞掉退出码**, `&&` 照常放行, ship 照跑（万幸 bump 内容已随
46aa5cfc0 落库, 树干净且安装版本一致, 无实际损伤）。

事后处置: 补 empty marker commit `3987dc5`（commit message 记录事故全过程）,
保持 `chore(release): bump to X` 链可 grep。

**教训再钉一遍**: `git commit` 的退出码必须单独捕获, 永远不要 `git … | tail && 下一步`
（0.5.124 起已两次踩坑, 本次第 5 次变体——这次是 add 范围与既有惯例冲突的放大器）。
防再犯: release bump 一律在**单独 commit、单独命令**里做, 不与任何 fix/feat commit
共享 add 路径。
