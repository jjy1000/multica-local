## Why no version bump

All 0.3.63 changes are security hardening + audit-stability fixes
(documented in commit `ef7ed4b`). No schema migration, no new
lab, no new UI surface. Bumping the version would have meant a
full release-note + bundle-cli + DMG cycle for code that does
not change any user-visible behavior — `apps/desktop/package.json`
stays at `0.3.62`.

## Why manual asar repack instead of `electron-builder --mac --dir`

`electron-builder` deadlocked at the `app-builder-bin@5.0.0-alpha.12
unpack-electron` step on macOS 27 (process 96908 stuck in
`pthread_cond_wait` with 0% CPU for 30+ min, identical pattern
observed twice in this session). The 0.3.62 ship log shows the
same command succeeded on 2026-07-23 21:08, so this is intermittent
on the alpha `app-builder-bin`. Killing the stuck process and
re-running did not help — the second run also deadlocked.

Fallback path (this ship):

1. `asar extract /Applications/Multica.app/Contents/Resources/app.asar
   /tmp/multica-0.3.62-extract` — 7.2 s, 615 MB extracted.
2. Overwrite `/tmp/multica-0.3.62-extract/out/` with the
   0.3.63 `apps/desktop/out/{main,preload,renderer}` from the
   14:36 electron-vite build.
3. Overwrite `/tmp/multica-0.3.62-extract/resources/bin/{multica,server,migrate}`
   with the 14:36 `apps/desktop/resources/bin/*` from
   `bundle-cli` (multica size delta +16 448 bytes = hardening patch).
4. `asar pack /tmp/multica-0.3.62-extract /tmp/multica-0.3.63-new.asar`
   — 19.3 s, 536 MB packed (vs 0.3.62 423 MB; size difference is
   asar compression parameter variation, extracted tree is identical
   615 MB / 48 597 entries).
5. `cp /tmp/multica-0.3.63-new.asar /Applications/Multica.app/Contents/Resources/app.asar`.
6. `cp apps/desktop/resources/bin/{multica,server,migrate}
   /Applications/Multica.app/Contents/Resources/app.asar.unpacked/resources/bin/`.

The 0.3.62 `app.asar.unpacked/` tree is reused intact — 0.3.63 does
not add, remove, or rename any resource path that child_process
spawns (no new lab, no new manifest, no new Python dep).

## Followups

- electron-builder alpha12 unpack-electron deadlock needs a real
  fix. Options: (a) pin app-builder-bin to a stable 4.x version
  (likely 4.x has no IPC pipeline), (b) wait for
  app-builder-bin 5.0.0 stable, (c) keep manual asar repack as
  the canonical 0.3.64+ path. **0.3.63 ship proves the manual path
  works end-to-end**, so option (c) is viable immediately. Will
  decide before 0.3.64.
- The 0.3.30.2 `grep -c rawRequest app.asar` check from
  `multica-0.3.30.2-labs-runtime-fixes-2026-07-16.md` is no
  longer directly applicable — the new asar compression
  parameters make `grep` against the asar binary header return 0
  even for strings that exist in extracted files. The
  `extract-file` + grep pattern also failed for the same
  reason (minified tokens). Replace with
  `asar extract-file … | grep -c` only after re-verifying on a
  known-good file, or replace with a feature-flag-based
  smoke test.

## §7 Config fix landed as a follow-up commit, not part of `ef7ed4b`

The `!dist/**` exclude + Step 0 `rmSync(distDir)` + CLAUDE.md
asar-links-out contract were left **uncommitted in the working
tree** at the moment of the 0.3.63 ship. They were applied to
the codebase (and to upstream 0.4.x where the Intel-DMG bug
fix originated) but `git status` after the manual asar repack
ship still showed them as modified.

Reason for the gap: the `electron-builder --mac --dir` deadlock
(see §5 above) meant the normal ship path never ran the code
that would have failed on these missing config lines, so the
fix felt cosmetic and was pushed down the todo list. The
ship was completed using the manual asar repack path, which
is immune to the dist/** contamination because it operates on
the already-packaged 0.3.62 asar.

**Same day, follow-up commit `eb9aa6f`** (after the ship):

```
fix(desktop): 0.3.63 — restore electron-builder !dist/** exclude
              + rmSync pre-clean (asar links-out)
```

Commit body documents the multica-ai/multica#5595 upstream
history, the `node-linker=hoisted` anti-pattern, and pins the
CLAUDE.md lesson so a future editor does not re-drop these
lines in a "tidy-up" pass.

**Implication for 0.3.64+**: the canonical ship path is still
`pnpm exec electron-builder --mac --dir`. With `eb9aa6f` in
place, that path is now correctly configured; if it still
deadlocks, we have isolated the cause to `app-builder-bin`
alpha12 (a `pnpm` issue, not a config issue) and the manual
asar repack path remains the verified workaround.
