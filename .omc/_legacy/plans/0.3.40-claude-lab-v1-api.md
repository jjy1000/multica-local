### 2. `POST /api/issues/{id}/lab-recompute`

**用途**:用户在 LabChatPanel / 重做按钮触发新一轮 agent run。

**请求**:
```
POST /api/issues/8c068c3d-.../lab-recompute
Headers:
  Authorization: Bearer <jwt|pat>
  Content-Type: application/json
Body:
{
  "workspace_id": "283d3de3-...",
  "prompt": "请用 Davis 数据集重做 (用户追加 prompt,可为空)",
  "rounds": 0    // 0 = 默认 10 轮,可选
}
```

**响应 201 Created**:
```json
{
  "task_id": "uuid-of-new-agent-task",
  "created_at": "2026-07-17T20:30:00+08:00"
}
```

**错误**:
- `400` prompt 长度 > 8KB
- `403` issue 不属于 workspace_id
- `404` issue 不存在 / 关联 agent 不存在
- `409` issue 已经有一个 running task(并发保护)
- `410` flag off
- `500` DB error

**实现**:
1. 校验 issue 存在 + workspace 匹配 + `lab_source='claude_science_lab'`
2. 校验是否有 running task(若已有,409)
3. 调 `assignDefaultLabAgent(issue, workspace)` 拿 agent(0.3.34 已有)
4. 调 `TaskService.EnqueueChatTask` 创建 agent_task_queue 行 + 同时绑 chat_session_id
5. 返回 task_id(daemon 会自动 claim 该 task)

### 3. `SSE /api/issues/{id}/lab-stream`

**用途**:实时推送 lab 状态变化,前端 use-lab-stream hook 订阅。

**请求**:
```
GET /api/issues/8c068c3d-.../lab-stream?workspace_id=283d3de3-...
Headers:
  Authorization: Bearer <jwt|pat>
  Accept: text/event-stream
```

**响应**:`text/event-stream; charset=utf-8`

**事件类型**:

```
event: task_update
data: {"task_id":"942eee4d-...","status":"running","updated_at":"2026-07-17T20:30:30+08:00"}

event: task_completed
data: {"task_id":"942eee4d-...","status":"completed","duration_ms":875000,"result_summary":"..."}

event: comment_added
data: {"comment_id":"187ee1cf-...","author_type":"agent","created_at":"2026-07-17T20:14:05+08:00"}

event: chat_message
data: {"message_id":"...","role":"user|assistant","content":"...","created_at":"..."}

event: heartbeat
data: {"ts":"2026-07-17T20:30:45+08:00"}
```

**心跳**:每 15s 一条 heartbeat 防止代理超时。

**生命周期**:订阅者断开 → handler context cancel → 释放资源;最长 5 分钟(防止连接僵死)。

**实现**:
- 后端维护 `labStreamHub map[issueID][]chan LabEvent`(in-memory)
- 触发点:agent task 状态转换(comment.go 的 `enqueueCommentAgentTriggers` 之后 / agent task 完成回调)
- 多订阅者 fan-out,每个订阅者独立 goroutine 写入
- panic recover(参考 forecastStream 的现有模式,避免触发 5xx burst blacklist)

## 前端 schema(写进 packages/core/types/api.ts)

```typescript
// zod schema,parseWithFallback 风格
export const LabIssueSchema = z.object({
  id: z.string().uuid(),
  workspace_id: z.string().uuid(),
  title: z.string(),
  description: z.string().nullable(),
  status: z.string(),
  lab_source: z.string(),
  lab_mode: z.enum(['sole','enhancer']).nullable(),
  assignee_id: z.string().uuid().nullable(),
  created_at: z.string(),
  updated_at: z.string(),
});

export const LabAgentSchema = z.object({
  id: z.string().uuid(),
  name: z.string(),
  description: z.string(),
});

export const LabTaskSchema = z.object({
  id: z.string().uuid(),
  status: z.enum(['queued','dispatched','running','preparing','waiting_local_directory','completed','failed','cancelled','deferred']),
  trigger_summary: z.string().nullable(),
  error: z.string().nullable(),
  failure_reason: z.string().nullable(),
  result_summary: z.string().nullable(),   // 提取自 result.output 前 200 字符
  created_at: z.string(),
  dispatched_at: z.string().nullable(),
  started_at: z.string().nullable(),
  completed_at: z.string().nullable(),
  duration_ms: z.number().nullable(),
});

export const LabCommentSchema = z.object({
  id: z.string().uuid(),
  author_type: z.enum(['member','agent','system']),
  content: z.string(),
  created_at: z.string(),
});

export const LabContextSchema = z.object({
  issue: LabIssueSchema,
  agent: LabAgentSchema.nullable(),
  tasks: z.array(LabTaskSchema),
  comments: z.array(LabCommentSchema),
  chat_session_id: z.string().uuid().nullable(),
  lab_seq: z.number().int(),
});

export const LabRecomputeRequestSchema = z.object({
  workspace_id: z.string().uuid(),
  prompt: z.string().max(8192).default(''),
  rounds: z.number().int().min(0).max(10).default(0),
});

export const LabRecomputeResponseSchema = z.object({
  task_id: z.string().uuid(),
  created_at: z.string(),
});

// SSE 事件 schema(runtime 用 zod 解析)
export const LabEventSchema = z.discriminatedUnion('event', [
  z.object({ event: z.literal('task_update'), data: z.object({ task_id: z.string(), status: z.string(), updated_at: z.string() }) }),
  z.object({ event: z.literal('task_completed'), data: z.object({ task_id: z.string(), status: z.string(), duration_ms: z.number().nullable(), result_summary: z.string().nullable() }) }),
  z.object({ event: z.literal('comment_added'), data: z.object({ comment_id: z.string(), author_type: z.string(), created_at: z.string() }) }),
  z.object({ event: z.literal('chat_message'), data: z.object({ message_id: z.string(), role: z.string(), content: z.string(), created_at: z.string() }) }),
  z.object({ event: z.literal('heartbeat'), data: z.object({ ts: z.string() }) }),
]);
```

## 关键变更点

1. **`result_summary` 字段**:不存 DB,从 `result` jsonb 实时提取(取 `result.output` 前 200 字符;若无,从 `agent_task_queue.error` 取前 200 字符)
2. **`chat_session_id`**:从 `chat_session WHERE issue_id=X` 取最近一条 active session(若不存在返回 null,前端引导用户"开始对话")
3. **`lab_seq`**:从 `agent_task_queue WHERE issue_id=X AND status IN ('completed','failed')` 计数 — 进度感
4. **不要给 result 加新列**:全部走 `result` jsonb 字段(已存在),handler 实时提取 summary

## 与现有架构兼容性

- **chat_input_task_id** (MUL-4351):lab-recompute 创建 task 时同时绑 chat_session_id,ChatWindow 用 chat_input_task_id 找到对应 task
- **assignDefaultLabAgent** (0.3.34):lab-recompute 复用,无需新逻辑
- **CLAUDE.md flag-off bypass**:所有新代码用 `{flagEnabled ? <NewCode /> : null}`
- **forward-only migration**:不删任何列,只读取 result jsonb
