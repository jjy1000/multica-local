# 实验室集成可用性提升 — ship 计划

**目标**:让用户开启任一 lab flag 后,真正的可观测行为符合用户契约:
1. 选 lab → 自动开始工作(任务问题可见)
2. 工作中 → 任务详情能看到状态
3. 完成 → 结果在「该实验室功能」可视化面板里,而不是散落在 issue 评论里
4. 桥接/自动化类开启后 → 不再出现在任务创建的可选 list 里(已经隐式开启)

**版本号**:0.3.54 / 0.3.55 / 0.3.56(分阶段 ship,每个 ship 都完整 ship 链)

---

## 用户契约分类

| 类别 | 标志 | 用户期望 | 现实 | 内部 Lab |
|---|---|---|---|---|
| **A. 工作台型** | 任务绑定 lab,有 workbench 多 tab | 选 issue → 跑 → 在 lab view 6 个 tab 看产出 | claude-lab 已经做到,其他 6 tab 弱 | `claude_science_lab`, `pythia_oracle`, `mythos_swarm`, `code_canvas` |
| **B. 自动化型** | 后台跑, 不需要 issue 上下文 | 开启后全局生效,任务里不需要选 | 已经 `HideFromIssueLabPicker` 不弹 | `agent_self_optimization`, `constitution_agent`, `llm_wiki_bridge` |
| **C. 编排型** | 工具, 不直接产出内容 | 入口 + 资源创建 | 已经实现 | `agent_creation_studio` |
| **D. UI 微调型** | 不属于以上 | 开启看效果 | 已经实现 | `chat_pin_ui` |

### 0.3.54 — 自动派单全覆盖 + UI 状态全覆盖

**目的**:用户选任何 issue 可绑定的 lab → leader agent 自动接管 → task 进队列 → IssueLabsSection 显示 running/queued/done 徽章。

#### 改动 1:扩展 `defaultLeaderAgentForLab` 包含所有 A 类 lab
`server/internal/service/issue.go:364`

```go
var defaultLeaderAgentForLab = map[string]string{
    "claude_science_lab":      "research",          // 已存在
    "constitution_agent":      "constitution_leader",// 已存在
    // 0.3.54: 全覆盖
    "pythia_oracle":           "pythia_runtime",    // 新装(0.3.25 manifest)
    "mythos_swarm":            "mythos_prelude",    // 已装
    "code_canvas":             "code_canvas_worker",// 新装(0.3.51 manifest)
}
```

(mythos_swarm 和 llm_wiki_bridge 等 hide-from-picker 的保持 no-op — 它们是 B 类)

#### 改动 2:IssueLabsSection 增加 idle/cancelled 状态指示
`packages/views/issues/components/issue-labs-section.tsx`

`indicator` enum 现在只有 running/queued。增加:
- `cancelled` — supervisor 显式取消
- `failed` — task 进队列后 rejection
- `idle` — 没有 running task(给 "点开 panel 看结果" 入口)

```tsx
const indicator = live.running ? {...} 
                 : live.queued ? {...} 
                 : live.failed ? {...} 
                 : null;
```

#### 改动 3:pythia_oracle leader agent 不存在时 graceful
0.3.54 之前:pythia_oracle 没装过 leader agent,`GetAgentByWorkspaceAndName` returns sql.ErrNoRows。当前 `assignDefaultLabAgent` 已经 swallow 这个 err,只 log "leader agent not installed"。

0.3.54 加一个**安装入口可见性** — 让 pythia_oracle flag 装上后,leader 也就绪(用户预期)。`install_pythia.go` / `install_code_canvas.go` 写 leader agent:

`server/internal/handler/install_pythia.go`(新):
```go
// 0.3.54: 注册 pythia_runtime leader
agentID, err := upsertLabAgent(ctx, h, workspaceUUID, "pythia_runtime", "Pythia 引擎", pythiaSkillID)
if err == nil {
    experimental.Claim(ctx, h.Queries, src, experimental.LockAgent, agentID)
}
```

#### 改动 4:user-facing 引导(每个 A 类 lab 详情加 "下一步做什么")

```tsx
        title="从主 issue 列表选一个问题,我会接管并开始研究"
        action={<Button onClick={pickFromIssueList}>选择问题</Button>}

```

具体每个 view:

| View | onboarding 文案 |

| Claude Lab | "在 Plan 标签选一个问题,我用多智能体 squad 给你查文献、写代码、可视化预测" |

## 风险与备选

### 风险 1 — auto-dispatch 可能误派单
0.3.46 的 P0#4 修复解决了 stale assignee 漏了 leader 的问题。但反向:用户**故意**选非 leader agent 当 assignee(罕见),然后开 lab。

**缓解**:仅当 `existing_assignee == nil OR != leader` 才 rewrite。0.3.46 已经实现,无新增风险。

### 风险 2 — code_canvas / pythia 安装路径新增 leader agent 会污染 AssigneePicker(像 0.3.53 那样)
**缓解**:install handler 调用 `experimental.Hide()` on lock row,**以及**调用 `upsert*Visibility` (0.3.53 pattern)。0.3.54 install_pythia.go / install_code_canvas.go 必须同时做。

### 风险 3 — 0.3.55 Code Canvas 产物是 image — base64 大文件浏览器压力
**缓解**:max 5MB,超过上传到 KB 库(Multica 已有 KB),给 .md viewer。
