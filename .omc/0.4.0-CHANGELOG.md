# Multica 0.4.0 — Changelog

> 0.4.0 是一次 schema-first fork 集成：保留 0.3.68 与 0.3.69 已 ship 的用户体验和稳定性修复，加入 upstream-040 的 wave 2 schema 迁移。0.4.0 本身没有新的 UI 或业务逻辑改动。
>
> 中文 UI / docs 文案遵循 [`apps/docs/content/docs/developers/conventions.mdx`](../apps/docs/content/docs/developers/conventions.mdx) 的术语与语气规范：简洁直白、错误提示温和明确，中英混排保留单空格。

## User-visible

- **Issue detail full-width（0.3.68）**：Issue detail 页面移除居中的 `mx-auto max-w-4xl` 限制，loading skeleton 与正文都使用可用面板宽度，长标题、宽表格和代码块不再被 4xl 列宽截断。Commit: `d7d99cf`。
- **Labs install-failure warning（0.3.69）**：启用实验室后，如果资源装载失败，Labs tab 现在显示警告 toast，并保留底层错误描述；偏好写入成功但 install 失败不再表现为静默空实验室。Commit: `991b71e`。
- **0.4.0 UI 状态**：无新的 UI 改动，属于 **schema-only** release；0.3.68 / 0.3.69 的 UI 行为由其 carryover commit 保留。Commit: `0e31df2`。

## Backend（Go）

- **Runtime GC 真实归档**：`runtime_gc.go` 将 0.3.19 遗留的 `tarGz` placeholder 替换为真实 gzip-compressed tar archive，采用临时文件加 rename 的原子写入；归档后的 runtime session 数据不再因后续 `RemoveAll` 被静默丢失。Commit: `991b71e`。
- **Installable sources 同步**：`installableSources` fallback 表补上 `pythia_oracle`（同时保留 `code_canvas`），与 live registry 保持一致。Commit: `991b71e`。
- **0.4.0 schema-only wave 2**：fork migrations `218–227` 已纳入集成，涉及 issue / task queue / agent / chat session 的索引与 additive columns；不含 Go application-code 改动。Commit: `36c18b7`。
- **Migration 218–227 列表**：`218_issue_workspace_assignee_index`、`219_issue_workspace_parent_index`、`220_issue_workspace_position_index`、`221_agent_task_queue_terminal_completed_at_index`、`222_agent_task_queue_agent_terminal_latest_index`、`223_agent_disabled_runtime_skills`、`224_chat_session_project`、`225_chat_session_project_index`、`226_agent_task_session_rollout_missing`、`227_agent_task_queue_retired_session_id`。Commit: `36c18b7`。

## Frontend（TypeScript）

- **`install_error` response contract**：API client 解析实验室 flag 更新响应中的 `install_error`，让 UI 能区分“偏好已启用”与“资源装载失败”。Commit: `991b71e`。
- **四语言 install warning**：新增 `labs.toast_install_warning`，覆盖 `en`、`zh-Hans`、`ja`、`ko`；中文文案遵循 conventions.mdx 的温和、明确错误语气。Commit: `991b71e`。
- **0.4.0 frontend 状态**：没有新的 TypeScript UI 改动，属于 **schema-only** release。Commit: `0e31df2`。

## Stability / correctness

- **`tarGz` stub 修复**：从 0.3.19 起的 11-byte placeholder 会返回 nil，调用方随后执行 `os.RemoveAll`，导致所谓“归档”实际删除 session 数据；0.3.69 的真实 tar.gz、tmp + rename 写入关闭了这一数据丢失路径。Commit: `991b71e`。
- **Runtime GC defer bug 修复（2026-07-28 audit）**：GC loop 不再在进入 loop 时提前关闭 `stopped` channel；关闭动作延后到 loop 退出路径，确保 sweep branch 可达并实际执行。Commit: `991b71e`。
- **Chi literal route 顺序**：`/sessions/by-issue` 必须注册在 `/sessions/{sessionID}` 之前，避免 literal `by-issue` 被参数路由捕获并误报 “sessionID is not a UUID”。该顺序契约由 Claude Lab route 修复确立。Commit: `cd30d9e`。
- **0.4.0 schema safety**：wave 2 migrations 使用 `IF NOT EXISTS` 守卫；生产 DB 验证显示 6 个新索引 `indisvalid=t`、3 个新 columns 已存在，且不会复活 cloud 调用路径。Commit: `3b5d3b1`。

## Repo infrastructure

- **6 个 AGENTS.md 镜像**：为 `apps/{desktop,mobile,web}`、`packages`、`packages/views`、`server` 增加 / 同步子域指南，作为根 `CLAUDE.md` 的可发现 digest。Commit: `d7d99cf`。
- **`check-agents-docs-sync`**：新增 `scripts/check-agents-docs-sync.mjs`，校验 `CLAUDE.md` 与 `AGENTS.md` parity 及关键约束 token，并接入 CI `docs-sync` job 与 pre-push hook。Commit: `d7d99cf`。
- **`boundaries.js`**：新增 `packages/eslint-config/boundaries.js`，配合 core / ui / views 的 ESLint 配置检查 package boundary。Commit: `d7d99cf`。
- **文档 / build infra 不进入 packaged app**：上述 AGENTS、docs-sync、CI 与 ESLint boundary 改动属于 repo infrastructure，不改变已 ship 的 renderer 或 Go binaries。Commit: `d7d99cf`。

## Release boundary

- **0.3.68**：renderer-only carryover，Issue detail full-width。Commit: `d7d99cf`。
- **0.3.69**：backend + frontend carryover，Labs install warning、真实 runtime GC tarGz、installable source sync。Commit: `991b71e`。
- **0.4.0**：upstream-040 Phase 1 schema-first integration，migrations `218–227`、cloud boundary audit 收口、desktop version bump；无新 UI / Go application logic。Commit: `0e31df2`。
