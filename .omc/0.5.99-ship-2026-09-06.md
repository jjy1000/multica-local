## TL;DR

0.5.99 ships the 1-line fix that unblocks 0.5.98 — `pickEnvForSpawn`
was re-exported from `server-manager.ts` without being imported
into the module's local scope, so every `spawn()` in the Electron
main process threw `ReferenceError: pickEnvForSpawn is not defined`
on first call, which the silent `try/catch` in `probeMulticaPg`
swallowed, looping 120 times over 60s and timing out `ensureServerUp`.
0.5.99 changes the re-export to `import { … } ; export { … }` and
cold-start passes in ~6s.

## Lessons (carries forward to 0.5.100+)

1. **Ship-chain verify must be fatal.** Cold-start verify is the
   ONLY check that exercises the Electron main process end-to-end.
   `ship-mac.sh` currently exits 0 even on verify failure, which
   masked the 0.5.98 regression at install time. **0.5.100 must
   make `step "7/7 cold-start verify"` fatal on FAIL** (already a
   `0.5.30` lesson documented but not enforced).
2. **Lint for unimported local references.** `pickEnvForSpawn` was
   referenced 3 times in `server-manager.ts` but the name was
   never imported — `pnpm typecheck` doesn't catch it because
   the bundler doesn't run typecheck on the source map. Add
   `typescript-eslint`'s `no-unresolved-references` /
   `no-redeclare` rules in `apps/desktop/eslint.config.mjs` and
   in `packages/.../eslint.config.mjs` for 0.5.100.
3. **Identical class to 0.5.25 RuntimeGC.** The audit fixed a
   code path but didn't ship its dependency, and the static
   checks didn't catch the missing piece. Document this
   pattern as a recurring "audit-fix-shall-ship-its-imports"
   pre-commit hook (lint check) in 0.5.100.
