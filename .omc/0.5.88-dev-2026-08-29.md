## WS1 — 委托闭环（server/CLI）

委托骨架 `multica lab delegate` 已存在（建 lab_source issue → 轮询 task-runs → stdout 输出），但结果只到 stdout、委托 issue 是孤儿、主 agent 不会被唤醒。本周期接上三根线：

1. **`lab delegate --parent [--stage]`**（`server/cmd/multica/cmd_lab.go`）：`--parent` 接受 issue key/UUID/UUID 前缀，解析完全镜像 `issue create` 的 `resolveIssueRef`（一种方言，不造第二套）；`--stage` ≥1 进入 stage 屏障组。委托成功后 **best-effort 把结果评论回传父 issue**（`postDelegateParentComment`，走 `issue comment add` 同一 client 路径，`[lab delegate] <flagKey> · <childKey> <title>` 头 + rune 安全 2000 字截断）；评论失败仅 stderr 警告，退出码仍反映委托结果。plain 模式 stdout 保持纯回复文本，child key 走 stderr。
2. **唤醒免费拿到**：child 带 `parent_issue_id` 后，既有 `handler/issue_child_done.go`「子终态 → 系统评论 mention 父 assignee」管道自动生效——**零守卫改动**，新 pin `TestChildDoneNotifiesParentForDelegatedLabChild` 证明 lab 形状（parent in_progress + agent assignee + lab child 空 assignee）会触发 mention + 恰一个 pending wake task。
3. **因果留痕**（`service/causal_graph/delegate_edge.go` 新文件 + `handler/issue.go` 创建成功路径挂接）：`parent_issue_id + lab_source` 同时存在时记 **parent --depends_on--> child** 边（既有 CHECK 集，无新边类型无迁移）；`Recorder.ensureIssueRootNode`（自 resolveTriggerNode 提取，行为等价重构）保证两端节点存在；any-status `FindCausalEdgeBetween` 幂等探针（0.5.84 ICP-5 never-nag）；provenance `{"source":"issue_delegate"}`；每条错误路径 WRN 返回，**issue 创建永因果写失败**。
4. **委托发现**（`service/causal_graph/delegate_brief.go` 新文件 + `handler/daemon.go` claim 注入）：`## Available Labs (delegation)` 小节列出 workspace 已启用的 assignee 型实验室（跳过 frozen 与 roster 型 mythos——无 leader 只会超时）+ 可复制的 `multica lab delegate --parent <issue-id> <flag-key> "<task>"`。2000 字节上限、200ms 预算、错误路径全返空串（claim_brief 同款隔离）；leader 解析器注入自 handler 既有 `resolveLabLeader`（不复制第三张表）；`context.WithoutCancel` 使查活在 claim 请求取消后仍完成。不挂在 causal_graph 旗下——该节宣传的是委托而非因果，空集即空节。
5. **DB pin**：`TestCreateDelegatedLabChildRecordsCausalDependsOnEdge`（端点/provenance/重放幂等）+ `TestDelegationBriefListsEnabledAssigneeLabs`（空集/列出/frozen 永不出现）。
