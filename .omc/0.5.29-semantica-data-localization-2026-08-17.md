## What this ships

### P0-2 (workspace isolation)
- `subprocess-manager.ts` validates `wsId` against `WS_ID_REGEX`
  (`^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$`)
  before any path interpolation. Invalid wsId → returns null +
  `console.warn` so the bug is visible without wedging IPC.
- Per-`(flagKey, wsId)` cache key. Pre-0.5.29 the singleton was keyed
  by flagKey only — switching the active workspace returned the
  cached manager, so WS-B inherited WS-A's process + graph.json +
  port + URL. The R5b silent-correctness failure mode is closed.
- `run.sh` derives `GRAPH_PATH` from
  `~/.multica/workspaces/<wsId>/semantica-graph.json`. Legacy
  `~/.multica/semantica-graph.json` is `cp`'d into the new path on
  first boot (one-shot migration), then left on disk as a backup.
- `run.sh` Python heredoc reads `wsId` from the `WS_ID_FOR_PY` env
  var, not string-interpolation — the R4 P0-2c RCE mitigation. The
  regex blocks `../foo` and `'; rm -rf /` payloads at the boundary;
  this script is defense-in-depth.

### P1-1 (X-API-Key INSIDE auth chain)
- `MountExperimentalProxies` moves **inside** the
  `r.Group(middleware.Auth(...))` block in `router.go`. The iframe
  stays same-origin, so cookies are auto-attached and
  `middleware.Auth` is transparent to the renderer.
- `reverseProxyTo.Director` **unconditionally** runs
  `req.Header.Del("X-API-Key")` before any conditional `Set` —
  the R4 TOP-1 mitigation. A conditional `if apiKey != ""` plus
  no `Del` would forward caller-supplied keys verbatim, turning
  the proxy into an unauthenticated credential oracle.
- Key transport is **in-memory** via `upstreamRegister` IPC. The
  pre-0.5.29 file at `$GRAPH_PATH.api-key` (0600) is gone — that
  file was reachable by any user-plugin `python3 -I` child
  (F-013 class surface).
- Per-launch key: `subprocess-manager.ts` generates a 32-byte hex
  string per spawn via `randomBytes`, threads it through
  `childEnv.SEMANTICA_API_KEY` to the subprocess AND through the
  IPC body to the server. Server stores in
  `Handler.ExperimentalFlagAPIKeys` (sync.RWMutex protected).

## Risk vs outcome

| Risk | Realized? | Outcome |
|---|---|---|
| iframe stops loading (auth chain wrap) | No | The iframe is same-origin (reverse proxy), cookies auto-attach, `middleware.Auth` is transparent. |
| Workspace switch breaks existing managers | No | The dispatcher re-resolves on every `ensure-up`/`stop` IPC; per-wsId cache means WS-A's manager keeps running when WS-B starts. |
| User-typed path-traversal wsId reaches disk | Blocked | subprocess-manager regex rejects; run.sh re-validates as defense-in-depth. |
| Caller-supplied X-API-Key granted by proxy | Blocked | R4 TOP-1 mitigation: unconditional `Del` in Director. |
| Per-launch key leaked to disk | Avoided | In-memory transport; no `*.api-key` file written by the spawn path. |
| subprocess-manager.test.ts call sites break | Mitigated | Threaded `WS_ID` through all 5 existing tests. |

## Post-ship callouts

- The `mode change 100644 => 100755` on `vendor/semantica/run.sh`
  is the `chmod +x` from the `bash -n` smoke step. The `git
  update-index --chmod=+x` path is preferred; we did `chmod +x`
  directly which git records as a mode change. Either is correct.
- `MountExperimentalProxies` moved from public router to auth
  group — no renderer-facing change required. The iframe keeps
  same-origin so cookies are auto-attached; `middleware.Auth` is
  transparent.
- `randomBytes` is the new dependency of `subprocess-manager.ts`.
  It's part of `node:crypto` (zero install cost, ships with Node).
- `experimentalFlagAPIKeys` map in `Handler` is **not** a cache
  pattern — it's the source of truth for the X-API-Key set by the
  desktop. The mutex is for concurrent `upstreamRegister` /
  `unregister` from the desktop main process during a manager
  restart. The lock window is one map access; we do **not** hold
  it across the proxy call.

## Lessons (next cycle)

- **Linter / file-watch interference during long commit chains.**
  The user / linter reset subprocess-manager.ts, run.sh, and the
  test file multiple times during this implementation. The
  pattern: write a smaller diff, commit more often. The 12-file
  commit at the end of this ship log would have been 4 atomic
  commits if I'd structured P0-2 and P1-1 as separate ships. The
  combined commit is harder to review.
- **In-memory transport > file transport for secrets.** The R4
  F-013-class surface (a per-launch file at 0600 reachable by any
  `python3 -I` child) is closed by making the desktop main process
  the key owner. The subprocess still needs the key in env
  (`SEMANTICA_API_KEY`) but the file path is gone. A future
  hardening pass should consider whether the subprocess even
  needs the key in env (could derive from a per-launch IPC round-
  trip), but that's a 0.5.30+ concern.
