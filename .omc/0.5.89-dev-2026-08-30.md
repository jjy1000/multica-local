## 本周期踩坑与教训
1. **agent.runtime_id 非空**（mig 004）：代建 agent 必须绑 runtime（选工作区最近 seen 的）；与 0.5.88 已知余留"daemonless 安装 NULL runtime_id"同一坑的镜像——这次在代建路径上直接规避了。
2. **`DELETE 204 → 200` 是行为变更**：按 0.3.64 惯例 grep 出 3 处 pin 同步更新（`user_plugins_crud_test.go`）；mock DB 按设计对未知 SQL fail-loud，新增 3 条查询路由（count/list/reclaim-status）+ mock Row 的标量 scan 通道。
3. **live 脚本三连坑**（都是脚本问题、非产品代码）：issue 更新是 PUT 非 PATCH；bash 变量中转会弄坏带反斜杠的 JSON payload（curl 直接 `-o` 落盘）；`CreateAgent` 会入队无 issue 的 **agent_intro 任务**，claim 前必须先清队列——前两个失败让 briefing 断言两次假阴性，最终 23/23 全绿前逐一归因修复。
4. **skill 表无软删列**：回收语义 = provisioned skill 硬删（有 origin 护栏，用户自建技能永不触碰）；declared skill 标 skipped 保留。
5. 两步删除拒绝发生在 plan 拉取之后（设计如此——两种模式都要先展示计划）；因此不写"先拒绝后网络"的单测，由 live 环 S5 断言覆盖。
