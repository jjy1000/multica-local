## 修复：issue 右键菜单导致的整应用卡死

### 现象

在 Issues 列表 / 看板 / 泳道 / 甘特图里右键 issue 打开操作菜单，点开"状态"子菜单选择状态后，偶发**点击无反应、整个应用不再响应任何鼠标操作**，只能重启恢复。卡死发生时屏幕上还会残留一个悬空的菜单（甚至出现在收件箱等根本没有右键菜单的页面）。

### 根因

每个列表行/看板卡/甘特行都挂着自己的一份右键菜单实例，且菜单默认以"模态"方式打开（打开时在窗口上铺一层透明遮罩 + 锁滚动）。当菜单里的操作（例如改状态）让这一行在界面上移动或消失时，这一行会连同**还打开着的菜单**一起被销毁；销毁路径清理不彻底，透明的遮罩层就永久残留，把整个窗口的点击全部吞掉——这就是"点击无反应 + 卡死"。

### 修复方式

对齐上游官方的结构重构（上游在同样的注释里称之为"切页卡死的最大单一来源"）：

- 每个视图表面（列表/看板/泳道/甘特）现在只有**一份**共享菜单，挂在视图层而不是行上——行怎么增删移动都影响不到打开中的菜单。
- 菜单仍在右击位置弹出，视觉与交互（状态/优先级/负责人/日期/固定/复制/删除全部子项）完全不变。
- 行高亮（`data-popup-open`）等细节契约保持一致。

### 升级与兼容

- 无数据库迁移；无配置变更；纯前端修复。
- 不改变任何键盘/快捷键行为；详情页 3-dot 菜单不在本次范围（其宿主与菜单同生命周期，暴露面不同）。
