#### MUL-6942 (C1) — issue id w-16 → min-w-16

identifier-span pattern was `packages/views/issues/components/list-row.tsx:105`.
Fork has no `table-view.tsx` and no `InlineTitle` component, so the

## MUL-7053 (C2) — codex retired-compaction 404 hint

Ported the path-keyed predicate (`CodexRetiredCompactionError`) + hint
constant + annotation function. Three deliberate divergences from
upstream:

1. `CodexResumeOverflowError` does not exist in fork (verified via grep).
   New code appended at the end of `server/pkg/agent/codex.go` rather than
   inserted after that function (the agent's plan said after it; main
   thread corrected this).
2. `annotateHermesProviderUnconfigured` does not exist in fork either.
   Only the codex leg is added in `daemon.go`; the call site comment
   documents the divergence so a future port does not think the line was
   missed.
3. Upstream's test files (launch-args + annotation) reference
   `NormalizeCodexLaunchArgs`, `codexFastServiceTier`, `FilterLaunchPrefix`,
   `stripCodexFastModeConflicts`, `classifyResumeUnsafeTransport`, and
   `service.ResumeUnsafeFailure` — none of which exist in fork. Carrying
   partially-adapted versions would give false confidence; the predicate
   table test (test 1) was ported verbatim because it only tests the
   new predicate, not the daemon annotation function.

When fork's launch-args infrastructure lands, the two skipped tests
should be ported together with that work — the hint's "launch arguments
are a real source" claim is what they verify.

## MUL-6923 (C3.1 + C3.2 + C3.3) — Cmd/Ctrl+1..9 tab select

3 of 4 sub-commits shipped. The 4th (settings UI row in `keyboard-shortcuts-
tab.tsx`) is **SKIPPED** because fork has no such component, no
`FixedShortcutRow` helper, and `createShortcutChord` is only used in
`thread-nav-panel.tsx` / `zoom-canvas.tsx`. Creating the full settings tab
from scratch is out of scope for 0.5.100.

The 8 orphan i18n keys (`select_tab_1_to_8` + `select_last_tab` × 4 locales)
added in C3.1 document the intended UI surface — they'll be wired to the
settings row when the tab is ported.

Inline `useCmdNumberTabSelect` lives next to the existing inline
`useCmdWCloseTab` in `App.tsx` rather than a separate hooks/ file —
matches fork's existing local pattern (no `use-open-settings-shortcut.ts`
in fork either).

Per user decision (B2-4): Cmd+9 selects the **9th tab**, not the last.
UI label `select_tab_1_to_8` describes 1–8 only; Cmd+9 maps to the 9th
position per upstream semantics.

## ship-chain verify fatal (C0) — the real win

`scripts/ship-mac.sh` step 7 now refuses to ship when:

1. `~/.multica/scripts/verify-desktop-cold-start.sh` is missing
2. The verify script exits non-zero
3. (new belt-and-suspenders) A server PID is not bound on :8090 after
   the script reports PASS
4. (new belt-and-suspenders) `/health` does not return
   `{"status":"ok"}` after the script reports PASS

The 0.5.98 regression (ReferenceError in `pickEnvForSpawn` shipped a
broken app) would have been caught by checks 3 and 4 even if the verify
script had exited 0 incorrectly. The verify script itself also exits
non-zero on these failures (`exit 2`), but the belt-and-suspenders layer
guarantees no future bug in the verify script silently bypasses the
ship gate.
