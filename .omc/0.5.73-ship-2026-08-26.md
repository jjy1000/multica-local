## Trigger

User feedback during 0.5.72 verification: clicking an experimental
plugin entry (e.g. "Claude Research Lab") in the Labs sidebar defaults
to a full-window view that hides the function bar (AppSidebar +
WindowToolbar). User should see the lab view WITH the sidebar, not
instead of it.

## Root cause analysis (5 min)

Walked the desktop navigation adapter
(`apps/desktop/src/renderer/src/platform/navigation.tsx`) and the
shell-gate logic (`apps/desktop/src/renderer/src/components/desktop-layout.tsx`).
Traced:

1. User clicks sidebar item → `useNavigation().push("/experimental/claude-lab")`
2. Navigation adapter: `extractWorkspaceSlug("/experimental/claude-lab")`
   returns `"experimental"` (first segment)
3. `"experimental"` is NOT in `RESERVED_SLUGS`
   → `tryRouteToOtherWorkspace` thinks this is a workspace switch
4. `switchWorkspace("experimental", "/experimental/claude-lab")` →
   creates new tab group keyed by `"experimental"` slug
5. `WorkspaceRouteLayout` (for slug `"jyf"`) unmounts
6. `setCurrentWorkspace(null, null)` called → singleton slug = null
7. `DesktopShell`'s `{slug && <AppSidebar />}` hides sidebar
8. Lab view renders full-window, function bar collapsed

## Lessons

- **Reserved slugs are load-bearing for desktop's per-tab workspace
  isolation.** The desktop navigation adapter uses `extractWorkspaceSlug()`
  to decide whether a path is a workspace-scoped route or a pre-workspace
  route. ANY new pre-workspace route prefix (`/experimental/*`,
  `/experimental/plugin/:slug`, future `/onboarding/*`, `/invite/*`,
  etc.) MUST be added to RESERVED_SLUGS or it will silently hijack
  navigation. The list is small but critical — and it's easy to forget
  because the failure mode (sidebar collapses to nothing) doesn't look
  like a navigation bug at first glance.
- **The `slug && <AppSidebar />` gate is the right design** — it's
  conservative and prevents `useRequiredWorkspaceSlug()` throws. The
  fix lives in the navigation adapter (upstream), not in the shell
  gate. Removing the gate would just trade one bug for another.
- **Pre-existing test failures are not always caused by your change.**
  `pnpm --filter @multica/core test` showed 3 failures; `git stash`
  baseline showed the same 3 failures — they predate this fix. Always
  baseline-verify before assuming your change broke a test.
