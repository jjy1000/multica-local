# 0.3.42 err.Error() 500-body leak audit — scope decision

## Decision

PR-1 (server hardening, 0.3.42) fixed the 3 sites in `lab.go::fetchLabContext*` (lines 318, 403, 543).

The remaining 13+ sites of the same pattern across `daemon.go` (and other handlers) are **deliberately NOT touched** in this ship because:

1. They are pre-existing (predate 0.3.41 v2 work by months)
2. They follow the project-wide style — changing them in a feature
   ship would create inconsistency ("why does lab.go use generic,
   but daemon.go still leaks err.Error()?")
3. The single-user fork threat model makes the leak lower risk than
   in a multi-tenant SaaS

## Follow-up

Open a separate audit + PR titled "0.3.43: project-wide 500-body
generic message + slog migration" that touches every site together.
This keeps the diff reviewable per-file and avoids mixed-style churn.

## Pattern to apply in the follow-up

Replace:

```go
writeError(w, http.StatusInternalServerError, "msg: "+err.Error())
writeJSON(w, http.StatusInternalServerError, map[string]string{"error": err.Error()})
```

With:

```go
slog.Error("handler-name op failed", "err", err, "key1", val1)
writeError(w, http.StatusInternalServerError, "msg")
```

For 400-class errors (validation), keep `err.Error()` — those
intentionally surface the constraint name to the developer.
