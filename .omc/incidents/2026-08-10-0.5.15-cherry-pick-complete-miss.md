# Incident: 0.5.15 cherry-pick complete-miss (`#6199` writeIssueBodyFormatting)

**Date**: 2026-08-10 (ship) → 2026-08-11 (caught by post-ship code-reviewer)
**Severity**: P0 (ship-blocker — ship gate had only `pnpm typecheck`, not `go test`)
**Versions affected**: 0.5.15 only (fixed by follow-up `da1cc2003`)
**Root cause**: Cherry-pick completeness check missed parallel code path in fork.

## Summary

Upstream `#6199` (avoid H1 headings in issue bodies) cherry-picked cleanly
but only wired `writeIssueBodyFormatting` into the **slim** brief path
(`buildMetaSkillContentSlim`). The fork's **legacy verbose**
`buildMetaSkillContent` path (default in production, gated by `useSlimBrief()`)
was missing the call site, breaking
`TestBuildMetaSkillContentIssueBodyFormatting` 4/4 subtests.

`pnpm typecheck` passed (catches missing TS imports) but `go test` was not
in the ship gate. The gap was caught only by post-ship `code-reviewer`
agent, NOT the ship gate.

## Three cherry-pick completeness miss classes

When porting upstream PRs to this fork, the cherry-pick filter must
verify all three classes before declaring ready-to-ship:

1. **Parallel code paths** — does upstream still have both `legacy` and
   `slim` / `v2` versions that the fork also has? Wire into both.
   *This incident*: `#6199` touched only slim path; fork's verbose path
   is production default.
2. **Referenced helpers / imports** — does the cherry-pick reference a
   function the fork has not ported? `#5980` mention-spaces referenced
   `itemArgs` from upstream `#4790` tiptap inline-code upgrade which the
   fork never back-ported. `pnpm typecheck` catches missing TS imports
   but **NOT** missing Go test helpers; always run `go test -count=1`
   after cherry-picking into `server/`.
3. **Test-path reachability** — the test may call
   `buildMetaSkillContent` directly (skipping the slim-brief gate); the
   assertion applies to the verbose path even though production code
   uses slim.

## Fix pattern

When upstream only touched one path but the fork has both, **mirror
upstream's call site into the fork's other path**, not the other way
around. Document each fixup as a separate `fix(execenv)` commit on the
same branch — never amend a previous cherry-pick into a release commit
(loses attribution).

`da1cc2003` followed this pattern: a 1-commit follow-up wiring
`writeIssueBodyFormatting` into `buildMetaSkillContent` (legacy path).

## Process gap closed

Ship gate must include `go test` in addition to `pnpm typecheck`. The
CLAUDE.md `Verification` section now states:

> Ship gate (mandatory) — before any release commit, BOTH of these
> must be green:
> - `pnpm typecheck` (full turbo pipeline) — catches TS breakage
> - `cd server && go test -count=1 ./internal/... ./pkg/agent/...` —
>   catches Go breakage
