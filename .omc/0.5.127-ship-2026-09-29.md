## 批 1 — 实验室委托断链（eab772925）

**根因**（两处叠加,均已活体实锤）:
1. `BuildDelegateBrief` 的 enabled 集合来自 `ListEnabledFlagKeys`（**pref-only 投影**）,
   而 claude_science_lab/pythia_oracle 0.5.114 起 `DefaultVal=true`——用户从未拨过开关
   → 无 pref 行 → **委托简报在默认安装上恒为空**。活库: pref 表只有 4 个已退役/辅助 key。
   Labs UI 用 `pickEnabled(DefaultVal, override)` 合并语义所以面板正常——两处语义不一致。
2. `multica-labs` 目录技能明说 claude_science_lab "⚠️ 需用户绑定 / 不要试图用 CLI 驱动"
   ——与事实相反（0.5.125 pythia 事故翻版）。

**修复**: `experimental.EffectiveEnabledKeys`（pickEnabled 合并语义）+ `ListAllExperimentalPrefs`
SQL + `selectDelegateLabs` 纯过滤; `issue create/update --lab-source`（客户端 fail-fast
未知/冻结 lab,空串=null 解绑）; 技能文案反转（✅ `multica lab delegate --parent <id>
claude_science_lab "<task>"`）; `multica-labs` 纳入 skill_cli_contract; 旧 DB 钉
`TestDelegationBriefListsEnabledAssigneeLabs` 反向重写（旧钉把 bug 当 empty-when-none 基线）。
钉子 needle 教训: 不能用"需用户绑定"裸子串——会误伤 pythia 的"**无**需用户绑定"。
