## 内容

### 核心改动:agent_creation_studio + agent_self_optimization 从"实验插件"升格为"主产品内建资源"

**0.5.5 之前**: 这两个 flag 是 opt-in Labs,用户必须:
1. 进 Labs tab 启用 flag
2. 触发 `multica experimental install agent_creation_studio` provision leader agent
3. 在 LabPicker 选 lab,server 0.3.46 P0#4 改写 assignee

**0.5.5**: 改为主产品内建资源:
- `agent_creation_studio` 改 catalog DefaultVal `false → true`,移除 `AlwaysShowInLabPicker`(picker 永远不列)
- `agent_self_optimization` 沿用 0.3.45.1 的"service 总在 boot 跑"设计(早就不在 picker)
- `agent_creation_expert` leader agent 由 `boot_provision_product_labs.go` 在 server boot 时自动 upsert 到每个 workspace(不写 `experimental.Claim`、不写 visibility hide —— 跟实验域完全解耦)
- `upsertAgentCreationExpert` 修了 0.3.35 时代未补完的 bug:boot 阶段 daemon 还没起,`runtime_id` 无 online runtime 可绑,加 `resolveOrSynthesizeProductRuntime` synthetic offline stub fallback(同 `upsertClaudeScienceRuntime` 模式);daemon 上线后 `rebindLabAgentsToOnlineRuntime` 自动 re-point 到 live runtime

### 用户视角的体验

- **Issue AssigneePicker**: 直接选 `agent_creation_expert`(智能体创建专家)/ `智能体优化专家`,**一步派单**
