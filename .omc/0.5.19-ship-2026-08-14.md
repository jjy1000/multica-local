## Lessons / prevention

1. **auth-proxy 设计必须在 chain-level bypass**（不是 handler-level）。Spec 文档写「handler verifies HMAC instead of requireUserID」是对的，但忽略了 **middleware 在 handler 之前运行** 这一 Go HTTP 链的事实。下次任何需要「anonymous-friendly」端点的设计必须：(a) 在 router layer 把端点放对 group，或 (b) 加 sig-aware middleware wrapper。Spec 模板加 1 行：「endpoints that must accept anonymous signed requests register OUTSIDE the main Auth group with a sig-aware wrapper」。
2. **usability smoke 必须在 ship 前跑**。前 6 个 commit 都没跑 M5 E2E — 若 ship 没在 usability smoke 测过，0.5.19 .app 会有 100% signed URL 失败回归。Ship gate 加 1 项：M5 E2E 6-vector smoke。
3. **6 → 4 commit 是 max buildable**（同 0.5.19 release notes）。文件交叉依赖图必须在 commit split 前画出来。
4. **设计 doc spec 也可能 stale**（同 0.5.17 lesson）。M3「需新增 read 端点」是过时信息；M4「只读历史」不能 standalone 工作；M5「handler-level bypass」不充分。**先 verify 再动手**——三次教训同源。
5. **bundle-cli output migration mirrors should be committed**。`apps/desktop/resources/server/migrations/*` 是 bundle 输出但同时 ship 在 .app 里。`bundle-cli` 不 git-add，所以这类文件容易遗留 untracked。M4 commit `baa1094de` 应同时 stage resource mirrors；HOTFIX commit 补救。
